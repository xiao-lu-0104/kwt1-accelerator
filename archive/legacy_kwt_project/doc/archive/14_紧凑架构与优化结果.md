# 紧凑版 encoder：资源复用、SRAM 与行处理

> 本文记录 V1（542,124 周期/单层，93 个 SRAM 宏）。当前默认实现已升级 V2，
> 见 [15_MAC流水与KV合并](15_MAC流水与KV合并.md)。V1 源码已冻结在 `rtl/reference/`。

本轮工作日期：2026-10-27。保留旧版单层 `kwt_encoder_layer` 作为数值与结构对照；
`kwt_encoder_12` 默认 `COMPACT=1`，使用新增 `kwt_encoder_layer_compact`。
设 `COMPACT=0` 可选择旧单层，十二层调度器的层间 SRAM 接口仍使用新版。

## 1. 统计边界

比赛要求硬件输入为 99×64，任务输出为十二层编码器结果，输入投影与分类头在软件侧。
因此新增综合脚本 `syn/run_compact.tcl` 的顶层为 `kwt_encoder_12`。
保留 `kwt_top` 的输入投影和分类头，用于三样本端到端回归。

原先的 2560 路矩阵乘法对应整个 `kwt_top`：8 套 encoder 引擎，加输入投影与分类头各一套。
同一 encoder 边界下，矩阵乘法资源由 8×256=2048 路变为一套 4×16=64 路，减少 96.875%。
整个 `kwt_top` 仍有 256+64+256=576 路，不能把 64 写成整机资源。
非线性、残差对齐、requant 等乘法不包含在这项矩阵 MAC 数中。

## 2. 已实现的数据流

1. 逐 token 计算 K/V，存入同步 SRAM，K 按四个 key 打包，V 按输出通道转置打包。
2. 读入一个输入 token，并保留该 token 的残差。
3. 共享 MAC 计算 Q；按四个 key 一组计算 score，直接写入单行 Softmax。
4. Softmax 保留该行 99 个概率；共享 MAC 计算 AV，再计算 O 投影。
5. 残差直接送入 `ROWS=1` 的 LayerNorm；保存归一化后的单行残差。
6. 共享 MAC 计算 FFN1，requant 后直接经过原 GELU 表，保存一行 256 维中间结果。
7. 共享 MAC 计算 FFN2；残差与第二次行 LayerNorm 后，将该行直接输出。
8. 继续下一个 token；输出送十二层调度器的 SRAM，用于下一层。

没有保存整张 Q、score、概率、ctx、O、FFN 中间矩阵或两张 int16 残差矩阵。
K/V、输入与本层权重是跨行复用的数据，仍需保留全量。

## 3. 大数组审计与消除

| 旧位置/对象 | 旧逻辑容量 | 新路径 |
|---|---:|---|
| attention.score_buf | 19,800 B | 99×int16 行缓存，位于单行 Softmax |
| attention.p_buf | 约 9,801 B | 99×uint8 行缓存 |
| encoder.h_buf | 25,344 B | 256×int8 行缓存，GELU 在写入时完成 |
| encoder.r1_buf/r2_buf | 各 12,672 B | 一次复用 64×int16 LayerNorm 行缓存 |
| LayerNorm.x_buf | 12,672 B | 128 B 行缓存 |
| encoder/attention/GEMM 私有激活副本 | 多份矩阵 | 一份输入 SRAM，加少量行寄存器 |
| 十二层调度器 xhold | 6,336 B 寄存器数组 | 16×4096 SRAM，打包两个 int8 |

新计算模块中的 `vec/result` 各 256 B；`xrow/ln1row` 各 64 B；`prob` 为 99 B。
它们是小型并行访问行寄存器。LayerNorm/Softmax 自身也有行缓存与参数寄存器，
不能把这些寄存器或相关多路选择器面积漏掉。

## 4. SRAM 物理组织

`kwt_mem16` 是 16-bit 宏适配边界，默认实现为同步读、整字写的行为模型。
`kwt_packed_sram` 用多个这样的宏拼接宽字；不依赖宏的 nibble/byte 写掩码。
局部写通过流水读改写实现，相邻同址写使用转发，保持每周期可接受一次更新。

| 对象 | 物理组织 | 指定 16-bit 宏数量 | 容量 |
|---|---|---:|---:|
| 本层 W4 权重 | 256×1024 | 16 个 16×1024 | 32 KiB |
| bias 与 multiplier | 64×1024 | 4 个 16×1024 | 8 KiB |
| 输入激活 | 128×1024 | 8 个 16×1024 | 16 KiB |
| K | 512×128 | 32 个 16×128 | 8 KiB |
| V | 512×128 | 32 个 16×128 | 8 KiB |
| 层间传递 | 16×4096 | 1 个 16×4096 | 8 KiB |
| **合计** | | **93 个宏** | **80 KiB = 655,360 bit** |

这是按允许宏规格取整后的容量，不是逻辑数据量；也不等于 FPGA 的 BRAM 物理 bit 数。
128 深度的小宏很多，宏外围开销与宽线代价需要用真实宏面积、时序重新评估。
后续可比较更窄 SRAM、多周期装载的方案，减少小宏数量。

读改写同时需要一个读口和一个写口，本配置需要双端口宏，不能直接绑定单端口宏。
宏读延迟为一拍。装载和计算读取互斥；窄权重写可逐元素输入，宽写需 16 元素对齐。
写入有一个待提交流水级，控制器在开始计算前提供了排空时间。

真实 ASIC 综合必须定义 `KWT_ASIC_SRAM`，并提供 `kwt_foundry_sram16` 适配模块，
将 `.clk/.we/.wa/.wd/.ra/.rd` 连接到实际宏的时钟、片选、写使能与地址端口。
适配模块支持 DEPTH=128/1024/4096，并使用库规定的读写冲突行为。
**目前没有工艺宏库，尚未完成这个绑定，不能宣称 ASIC SRAM 映射或面积达标。**

## 5. 数值规则与时序

权重、激活、标定、scale、bias、饱和、舍入与查表内容不变。
W4 权重先符号扩展为 int8，再使用共享 MAC；QKᵀ/AV 使用 int8。
每 16 项的精确和累加到 int32，保持模 2^32 的原 RTL 累加语义。
整数求和分段变化不改变最终结果；LayerNorm 与 Softmax 仍按原算法逐行处理。

第一次综合发现原 Softmax 的单周期除法形成约 55 ns 的 FPGA 数据路径。
紧凑版启用 `SERIAL_DIV=1`：27 次移位/减法，精确计算 `(127<<20)/sum`，
增加每行 27 拍，不改变取整与概率输出。旧模块默认仍使用原实现，便于对照。

这是优先缩面积的配置，计算周期增加。150 MHz 下的毫秒数只表示周期换算，
不代表时序已达标；真实参数总线等待、E203 调度与结果写回仍需平台集成评测。

## 6. 复现

```powershell
./sim/run_all.ps1 -SkipVectors
# 可选：同时运行旧计算后端的十二层对照
./sim/run_all.ps1 -SkipVectors -CompareLegacy
D:/Xilinx/Vivado/2022.2/bin/vivado.bat -mode batch -source syn/run_compact.tcl
```

仿真继续使用既有单层、十二层与整机参考向量。新 MAC 有独立标量参考测试，
包含随机值、边界值、int32 回绕、有效信号间隙与复位。
SRAM 测试覆盖三个合法深度、连续同址局部写、交错地址、零掩码和复位保留数据。

原独立 Softmax 的 expect.mem 有 334 个值落后于当前 `fixed_softmax.py` 的舍入规则。
本轮先确认旧 RTL 和新迭代除法均报同样差异，再运行 `tools/gen_softmax_vectors.py`
按现有软件模型重新生成；两种除法均通过 60×99 个值。没有修改软件数值模型。

## 7. 本机综合实测

最终迭代除法配置的单层输出 6,336 值逐位通过，计算 542,124 周期；
十二层输出 6,336 值逐位通过，含本地参数扫描与层间搬运共 6,700,681 周期，
按 150 MHz 换算为 44.67 ms。该计数从调度器 start 起算，不包含任务开始前
输入装载、真实总线等待与 E203 调度，不能直接作为赛题吞吐。

相同向量、相同新版层间 SRAM 接口下，`COMPACT=0` 旧计算后端也通过十二层逐位测试，
共 1,577,605 周期。紧凑版矩阵 MAC 路数减少 32 倍，周期约为旧后端的 4.25 倍。
这是资源与速度的对照，不是同库 ASIC 面积或能耗对照；旧后端尚未用同边界重新综合。

配置：Vivado 2022.2，Artix-7 XC7A100T-2，顶层 `kwt_encoder_12`，COMPACT=1，
150 MHz 约束，输入/输出延时各 2 ns。为综合后估计，未布局布线。

| 项目 | 结果 |
|---|---:|
| FF | 15,370 |
| LUT（含 LUTRAM） | 28,776 |
| RAMB36 / RAMB18 | 2 / 92 |
| FPGA DSP | 44 |
| 指定 SRAM 宏规格的总容量 | 80 KiB |
| Worst setup slack | -20.355 ns，未满足 150 MHz |
| 未约束内部端点 / 缺输入延时端口 | 0 / 0 |

FPGA DSP 数与矩阵 MAC 路数不是同一指标，8-bit 乘法也可能映射到 LUT。
FPGA BRAM 的最小粒度不同，不能用 FPGA BRAM bit 数替代赛题的 SRAM 宏容量。

当前最差路径位于 LayerNorm 的 Newton 迭代：同周期经过平方、方差乘法、
更新乘法，报告数据路径约 26.885 ns。下一轮应将其拆成多周期运算，并继续检查
LayerNorm 输出乘法、requant 与 MAC 路径。不能通过放宽时钟或添加虚假的多周期约束宣称达标。

生成报告：`syn/compact_v1_out/utilization.rpt`、`timing.rpt`、`timing_paths.rpt`。
当前可证明面积优先配置能够在本机完成综合，不能据此认定比赛 ASIC 面积、时序已经达标。

旧文档的“20 个宽 SRAM 宏”“28nm 面积估算”已加历史说明。
打包脚本改为使用当前 `rtl/tb` 和仿真向量，避免把旧 verified 快照与新版回归脚本混装。
