## 1. 层次结构

```
e203_soc_top
 └── e203_subsys_top
      ├── e203_subsys_main        ← CPU + 总线信号声明
      │    ├── e203_cpu_top        ← ICB 1→N 分发（ppi/clint/plic/fio/mem）
      │    ├── e203_subsys_hclkgen
      │    ├── e203_subsys_plic
      │    ├── e203_subsys_clint
      │    ├── e203_subsys_perips
      │    └── e203_subsys_mems   ★ 关键文件
      └── ...
```

`e203_subsys_main` 里声明了 5 组 ICB 信号：`ppi_icb_*`、`clint_icb_*`、`plic_icb_*`、
`fio_icb_*`（`E203_HAS_FIO`）、`mem_icb_*`。真正的地址分发在 `e203_cpu_top`
（core 内）和 `e203_subsys_mems`（fab 内）两处。

## 2. 存储总线地址映射（`e203_subsys_mems.v`）

`mem_icb_*` 进 `sirv_icb1to8_bus`（ICB 1→8 分路器），8 个出口的地址窗口如下：

| 出口 | 基地址 | `BASE_REGION_LSB` | 窗口大小 | 归属 |
|---|---|---|---|---|
| O0 | `0x0000_0000` | 12 | 4 KB | DM（调试模块） |
| O1 | `0x0000_1000` | 12 | 4 KB | MROM |
| O2 | `0x0002_0000` | 17 | **128 KB** | **未使用** |
| O3 | `0x2000_0000` | 29 | 512 MB | QSPI0 只读 |
| O4 | `0x8000_0000` | 31 | 2 GB | SysMem |
| **O5** | **`0x4000_0000`** | **28** | **256 MB** | **示例 AXI 外设 ← 加速器挂这里** |
| O6 | `0x0000_0000` | 0 | 禁用 | 未使用 |
| O7 | `0x0000_0000` | 0 | 禁用 | 未使用 |

## 3. 平台已预留的扩展点

O5 通路**已经接好了一整套示例外设**，这是官方设计的"加你自己的外设"入口：

```
mem_icb_*  ──►  sirv_icb1to8_bus (O5, 0x4000_0000)
                      │
                      ▼
                sirv_gnrl_icb2axi        ICB → AXI4（full）
                      │
                      ▼
                sirv_expl_axi_slv        示例 AXI 从机  ★ 用我们的加速器替换它
```

**结论修正**：不需要写 ICB 从机。**要写的是 AXI4（full）从机**，
直接替换 `sirv_expl_axi_slv` 的位置，地址段 `0x4000_0000` 起。

> 之前 `doc/ICB总线协议.md` 里的 ICB 从机方案作废 —— ICB 层由平台的
> `sirv_gnrl_icb2axi` 负责转换，我们只需面对 AXI4。

### 与现有 RTL 的差距

| 项 | 现状 | 需要 |
|---|---|---|
| 总线 | `kwt_axi_slave.v` 是 **AXI4-Lite**（无 burst） | **AXI4 full**：需支持 `arlen`/`awlen` 突发、`rlast`/`wlast` |
| 被包裹的核 | `kwt_axi_top.v` 里是旧核 `kwt_top` | 应改为 `kwt_encoder_12` |

`sirv_gnrl_icb2axi` 实例化时 `i_icb_cmd_burst` 由上游决定，CPU 的 LSU 访问可能是
单拍也可能是突发，**必须按 full AXI4 处理**。

## 4. 最大的未决问题：288 KB 参数放哪

### 4.1 参数量

| 内容 | 每层 | 12 层合计 |
|---|---|---|
| Q/K/V/O 权重（4 × 4096 nibble） | 8,192 B | 98,304 B |
| FFN1/FFN2 权重（2 × 16384 nibble） | 16,384 B | 196,608 B |
| 偏置 / 乘子 / LN gamma+beta / 常量 | ~2.6 KB | ~31 KB |
| **合计** | | **≈ 288 KB（int4 打包）** |

### 4.2 片内放得下吗？放不下

- 已有 SRAM：80 KiB（0.710 mm²）
- 再加 288 KB：按 0.558 µm²/bit（RAMSP1024X16）估算约 **1.29 mm²**
- 总面积会变成 0.97 + 1.29 ≈ **2.26 mm²**，**超出 2.25 mm² 预算**

所以参数**必须放在片外或系统存储里**。

### 4.3 三条可选路线

| 方案 | 做法 | 代价 |
|---|---|---|
| **A. 加速器做 AXI 主设备** | 加一个 AXI master 口，从 SysMem（`0x8000_0000`）流式读参数 | 需要额外的 master 口 + 仲裁；平台有 `sirv_gnrl_icb_arbt` 可用 |
| **B. 外设自带参数 RAM** | 加速器旁挂一块 288 KB SRAM，CPU 先写入 | 面积超标，ASIC 不可行；FPGA 上可用 BRAM 凑 |
| **C. QSPI Flash 直读** | 加速器加 QSPI 控制器读 Flash | 实现最复杂，但最贴近真实芯片 |

**FPGA 原型阶段推荐 B**（Artix-7 有 135 个 RAMB36 = 4.86 Mbit，够放 288 KB），
**ASIC 阶段必须走 A 或 C**。

### 4.4 无论哪条路线，`kwt_encoder_12` 都要改

当前 `rom_*` 是**零延迟**接口：

```verilog
wire ld_wgt = (state == S_LW);            // 组合，与 ld_addr 同拍
.p_wgt_we16(ld_wgt), .p_wgt_data16(rom_wgt16),
```

必须加 `rom_valid` 停拍握手（详见 `doc/ICB总线协议.md` 第 8.3 节）：

- `rom_valid` 低 → `cnt` / `ld_addr` 不推进
- `ld_wgt` 保持高、数据保持稳定 → 层内"重复写同一地址同一值"，幂等无副作用
- 不需要门控 `we`，改动只有几行

外部只需保证：给定单调递增的 `ld_addr`，`rom_valid` 在数据就绪时拉高。

## 5. 实施顺序

| 阶段 | 内容 | 依赖 |
|---|---|---|
| **P1** | `kwt_encoder_12` 加 `rom_valid` 停拍握手，默认常高保持 bit-exact | 无 |
| **P2** | AXI4 full 从机（可由 `kwt_axi_slave` 升级），包 `kwt_encoder_12` | P1 |
| **P3** | 参数通路（FPGA 先用 B，ASIC 再换 A/C） | P1 |
| **P4** | 替换 `sirv_expl_axi_slv`，跑通 SoC 仿真 | P2、P3 |
| **P5** | C 驱动 | P4 |
