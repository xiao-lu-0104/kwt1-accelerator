## 1. ICB 是什么

本 SoC 采用**蜂鸟 E203** 内核开发过程中定义的一种自定义总线协议 **ICB**（Internal Chip Bus）。
该总线原本用于 E203 内核内部，同时也可作为 SoC 中的总线使用。

设计初衷：尽可能结合 AXI 总线和 AHB 总线的优点，兼具高速性与易用性。

## 2. ICB 的特性

- **协议控制更简单**：仅有两个独立通道（命令通道 + 返回通道），读和写操作**共用地址通道、共用结果返回通道**。
- **与 AXI 一样采用分离的地址和数据阶段**（地址与数据不同拍）。
- **与 AXI 一样采用地址区间寻址**，支持任意的主从数目（一主一从、一主多从、多主一从、多主多从）。
- **与 AHB 一样每个读或写操作都会在地址通道上产生地址**（不像 AXI 只在突发首拍产生起始地址）。
- **与 AXI 一样支持地址非对齐的数据访问**，使用字节掩码（Write Mask）控制部分写操作。
- **与 AXI 一样支持多个滞外交易**（Multiple Outstanding Transaction）。
- **与 AHB 一样不支持乱序返回乱序完成**，**反馈通道必须按顺序返回结果**。
- **与 AXI 一样非常容易添加流水线级数以获得高频的时序**。

## 3. 通道结构（图 4-1）

```
      命令通道（地址和控制信息，逐笔）
主接口 ──────────────────────────────► 从接口
      返回通道（返回结果，逐笔，顺序）
主接口 ◄────────────────────────────── 从接口
```

两个通道均为逐笔握手：每一笔读或写都在命令通道上占一拍（或多拍等待），
对应的结果在返回通道上按**发起顺序**逐笔返回。

## 4. 信号列表（图 4-2）

> ⚠️ 下表"方向"是**主设备视角**（原文如此）。做从机时需要全部取反，见第 6 节。

| 通道 | 方向 | 宽度 | 信号名 | 说明 |
|---|---|---|---|---|
| Command | Output | 1 | `icb_cmd_valid` | 主设备向从设备发送读写请求信号 |
| Command | Input | 1 | `icb_cmd_ready` | 从设备向主设备返回读写接受信号 |
| Command | Output | 32 | `icb_cmd_addr` | 读写地址 |
| Command | Output | 1 | `icb_cmd_read` | 读/写指示。读则以总线宽度（32 位）为单位读回一个数据；写则靠字节掩码 `icb_cmd_wmask` 控制写数据的大小（Size） |
| Command | Output | 32 | `icb_cmd_wdata` | 写操作的数据，数据摆放格式与 AXI 协议一致 |
| Command | Output | 4 | `icb_cmd_wmask` | 写操作的字节掩码，摆放格式与 AXI 协议一致 |
| Response | Input | 1 | `icb_rsp_valid` | 从设备向主设备发送读写反馈请求信号 |
| Response | Output | 1 | `icb_rsp_ready` | 主设备向从设备返回读写反馈接受信号 |
| Response | Input | 32 | `icb_rsp_rdata` | 读反馈的数据，数据摆放格式与 AXI 协议一致 |
| Response | Input | 1 | `icb_rsp_err` | 读或写反馈的错误标志 |

## 5. 时序规则（图 4-3 ～ 图 4-8）

### 图 4-3　写操作，结果同拍返回

主设备通过 Command Channel 发送**写**请求（`icb_cmd_read` 为低），
从设备**立即接收**该请求（`icb_cmd_ready` 为高）。
从设备**在同一个周期**返回写结果且结果正确（`icb_rsp_err` 为低），
主设备立即接收该结果（`icb_rsp_ready` 为高）。

### 图 4-4　读操作，结果下一拍返回

主设备发送**读**请求（`icb_cmd_read` 为高），从设备立即接收（`icb_cmd_ready` 为高）。
从设备**在下一个周期**返回读结果且结果正确（`icb_rsp_err` 为低），
主设备立即接收该结果（`icb_rsp_ready` 为高）。

> 这是读操作的**最小延迟**：`rsp_valid` 最早出现在 `cmd_valid & cmd_ready` 的下一拍。

### 图 4-5　写操作，结果下一拍返回

写操作同样允许在下一个周期才返回结果。

> 由此可知：**写的结果返回时机是"同拍或更晚"，读的结果返回时机是"至少晚一拍"。**

### 图 4-6　连续 4 个读，第 4 个报错

主设备连续发送四个读请求（`icb_cmd_read` 为高），从设备均立即接收（`icb_cmd_ready` 为高）。
从设备**在四个周期后连续返回四个读结果**，其中前三个结果正确（`icb_rsp_err` 为低），
第四个结果错误（`icb_rsp_err` 为高），主设备均立即接收此四个结果（`icb_rsp_ready` 为高）。

> 关键点：**多 outstanding 时返回顺序必须与请求顺序一致**，不允许乱序。

### 图 4-7　连续 4 个写，第 4 个报错

与图 4-6 对称，写通道同样支持多 outstanding 且有顺序要求。

### 图 4-8　混合读写 + 两侧反压

主设备连续发送三个读/写操作请求。从设备立即接受了第一和第三个请求，
但**第二个请求在第一个周期并没有立即接受**（`icb_cmd_ready` 为低），
因此**主设备一直将地址、控制、写数据信号保持不变**，直到下一周期该请求被从设备接受（`icb_cmd_ready` 为高）。

从设备对第一和第二个请求都是**在同一个周期**就返回结果且被主设备立即接受；
但对第三个请求是**在下一个周期**才返回结果，且**主设备还没有立即接受**（`icb_rsp_ready` 为低），
因此**从设备一直将返回信号保持不变**，直到下一周期该返回结果被主设备接受。

> 两条反压（back-pressure）规则：
> - 主设备侧：`cmd_valid` 拉高后若 `cmd_ready` 为低，必须**保持 addr/read/wdata/wmask 不变**。
> - 从设备侧：`rsp_valid` 拉高后若 `rsp_ready` 为低，必须**保持 rdata/err 不变**。

## 6. 从设备（Slave）视角的信号方向

原文表格是主设备视角，做加速器 ICB 从机时方向全部取反：

| 信号 | 从机方向 | 位宽 |
|---|---|---|
| `icb_cmd_valid` | **输入** | 1 |
| `icb_cmd_ready` | **输出** | 1 |
| `icb_cmd_addr` | **输入** | 32 |
| `icb_cmd_read` | **输入** | 1 |
| `icb_cmd_wdata` | **输入** | 32 |
| `icb_cmd_wmask` | **输入** | 4 |
| `icb_rsp_valid` | **输出** | 1 |
| `icb_rsp_ready` | **输入** | 1 |
| `icb_rsp_rdata` | **输出** | 32 |
| `icb_rsp_err` | **输出** | 1 |

### 最小可用实现

一次只接收一笔请求即可天然满足"按序返回"：

```verilog
// IDLE : cmd_ready = 1'b1
//        若 cmd_valid 则接收，转 RESP
// RESP : rsp_valid = 1'b1，rsp_rdata/rsp_err 保持
//        等待 rsp_ready 后转 IDLE
```

代价是每笔访问至少 2 拍，对本设计的访问量（参数装载 / 少量寄存器访问）完全可接受。

## 8. 对本项目的落点分析

### 8.1 现有 RTL 的状态

| 文件 | 现状 | 结论 |
|---|---|---|
| `rtl/kwt_axi_slave.v` | AXI4-Lite 从机，寄存器映射 `CTRL/STATUS/PRED/CYCLES/NFRAMES/MFCC/ACT` | 寄存器逻辑可复用，**总线接口需换成 ICB** |
| `rtl/kwt_axi_top.v` | 例化 **`kwt_top`**（FPGA 版 Gen2 核，靠 `pp_wgt/cp/rom_wgt/hd_wgt` 外部端口喂权重） | **挂错核了**：ASIC 版应例化 `kwt_encoder_12` |
| `rtl/kwt_encoder_12.v` | 已通过 SMIC 40nm 综合，150 MHz WNS +0.068 ns，0.26 mm² | SoC 集成应包这个 |

### 8.2 `kwt_encoder_12` 的接口

```
start                          触发一次推理
x_we / x_addr[12:0] / x_data[7:0]        输入激活写入（8 bit/拍）
out_we / out_addr[12:0] / out_data[7:0]  输出激活读出（8 bit/拍）
cur_layer[3:0] / ld_sel[3:0] / ld_addr[13:0]   参数 ROM 扫描地址（输出）
rom_wgt[3:0] / rom_wgt16[63:0] / rom_bias[31:0] / rom_m[31:0]
rom_ln_gamma[15:0] / rom_ln_beta[15:0]         参数 ROM 数据（输入）
done / cycle_count[31:0]       状态
```

### 8.3 最大的难点：304 KB 参数从哪来

参数总量 **607,308 × 4 bit ≈ 304 KB**，远超片内 SRAM 预算（规划 80 KiB），
必须放在 SoC 层的片外存储（QSPI Flash 或主机下发的内存）里。

每层推理前 `kwt_encoder_12` 会**顺序扫描**参数 ROM（FSM 逐状态实测）：

| 状态 | 扫描内容 | 宽度 / 拍 | 拍数/层 |
|---|---|---|---|
| `S_LW` | Q/K/V/O 权重（4 × 4096 nibble） | `rom_wgt16[63:0]`，16 nibble/拍 | 1,024 |
| `S_LW` | FFN1/FFN2 权重（2 × 16384 nibble） | `rom_wgt16[63:0]`，16 nibble/拍 | 2,048 |
| `S_LBQ` | Q/K/V 乘子（192 字） | `rom_m[31:0]`，1 字/拍 | 192 |
| `S_LBO` / `S_LBF1` / `S_LBF2` | O / FFN1 / FFN2 偏置乘子（64+256+64） | `rom_bias`+`rom_m`，1 字/拍 | 384 |
| `S_LLN` / `S_LLC` | LN gamma+beta（128）+ 层常量（6） | `rom_ln_*` / `rom_m`，1 字/拍 | 134 |
| **合计** | | | **3,782 拍/层** |

12 层共 **45,384 拍 ≈ 0.30 ms @150 MHz**，占 21.6 ms 总推理时间的 **1.4%**，可接受。

### ⚠️ 关键障碍：当前 ROM 接口是零延迟的

```verilog
wire ld_wgt = (state == S_LW);           // 组合逻辑，与 ld_addr 同拍
wire ld_bp  = (state == S_LBQ) || (state == S_LBO) || ...;
wire ld_ln  = (state == S_LLN);
// 且 rom_wgt16 / rom_bias / rom_m / rom_ln_* 直接进层内写口
.p_wgt_we16(ld_wgt), .p_wgt_data16(rom_wgt16),
```

也就是说 **ROM 数据必须与 `ld_addr` 同拍到达**，等价于一个组合读存储器。
304 KB 不可能用触发器实现，而给定的 SRAM 宏全是同步读（1 拍延迟），
QSPI Flash 更慢（数十拍）。**直接接总线会无法工作。**

#### 推荐改法：加 `rom_valid` 握手，让 FSM 可以停顿

扫描地址严格单调递增，所以只需：

```verilog
// kwt_encoder_12 新增输入
input wire rom_valid;   // 外部参数通路给出「当前 ld_addr 对应数据已就绪」

// 各装载状态里的推进条件全部加 rom_valid 门控
// 例：S_LW
if (!rom_valid) begin
    // 保持 cnt / ld_addr 不变
end else if (cnt >= wlen(sel) - 16'd16) begin ... end
else begin cnt <= cnt + 16'd16; ld_addr <= ld_addr + 14'd16; end
```

**为什么停顿时不写脏数据**：`ld_addr` 不推进时，`ld_wgt` 保持为高、数据保持不变，
层内写口就是「往同一地址重复写同一个值」—— 幂等，无副作用。
所以不需要额外门控 `we`，改动面很小。

外部只需保证：给定单调递增的 `ld_addr` 序列，`rom_valid` 在数据就绪时拉高。

#### 外部参数通路的两种选择

| 方案 | 延迟吸收方式 | 适用 |
|---|---|---|
| 片内参数 SRAM（若放得下） | 同步 SRAM 输出打一拍，`rom_valid` 恒为 1（首拍除外） | 参数 ≤ 80 KiB，本设计 304 KB **放不下** |
| 片外 QSPI Flash + 流式预取 FIFO | 顺序扫描天然适合流式预取，FIFO 非空则 `rom_valid=1` | **本设计的现实选择** |

因为地址严格顺序递增，预取 FIFO 只需按 16 nibble 一组连续预取即可，
不需要随机访问，实现比通用 cache 简单得多。
