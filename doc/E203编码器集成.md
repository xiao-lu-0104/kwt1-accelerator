# E203 C 驱动与编码器集成候选（2026-10-30 v12）

前置 v11 服务器真实宏 AXI 回归已通过：6336 字节逐位一致，核心计数 3476758，
外设诊断计数 3502109，见 [MMIO 接口](MMIO接口.md)。这些计数来自总线功能主机。
本步骤将主机替换为实际执行 RISC-V 指令的 E203，运行 `sw/kwt_encoder.c`。

## 当前验证状态

- RV32 C 程序、启动汇编、ELF 和双 TCM 镜像已生成，包含完整输入及十二层参数。
- 本地参考 E203 SoC 的 C 短测试已通过，覆盖启动、签名读取、输入写入/计数和复位。
  本地参考平台只在隔离副本将 TCM 容量设为服务器已有的 256 KiB，并补顶层头文件，
  以适配 XSIM 的文件预处理方式；不能代替竞赛平台的服务器结果。
- 本地 XSIM 的原 `sirv_gnrl_xchecker` 在首次门控时钟边沿触发并发断言。
  PLIC 波形记录显示该检查使能一直为 0、复位仍为 0。
  本地诊断副本将其改为同一时钟和同一 X 谓词的事件检查，短测试随后通过。
  这是本地兼容性诊断，**不作为原并发断言已通过的证据**。
- 服务器运行器不带上述本地修改，保留全部原 CPU 检查器和断言。
  服务器实际 C 短测试及完整十二层 CPU 任务仍待执行；完整任务成功后才记录 CPU 周期。
- CPU 测试不是本轮逻辑综合、真实 PLL、布局布线或时序签核结果。

## 测试路径及隔离

`tb/tb_kwt_e203.v` 实例化原 `e203_soc_top`，沿用其复位、AON/PMU 和 boot ROM 路径，
从 ITCM 的 `_start` 进入 C 程序。只给外部时钟和复位 pad 激励。
CPU 经原平台 ICB→AXI 桥读写编码器接口；TB 不充当 MMIO 主机。
CPU 的 ITCM/DTCM 继续用竞赛行为存储配置，加速器用服务器原始 RAMTP 模型。

脚本优先复制 `vsim/install/rtl`，不存在则复制 `rtl/e203`，输出到新的 `kwt_e203_*` 目录。
`prepare_e203_kwt.py` 核对原外设文件 SHA-256、现有 TCM 容量及 mcycle 开关，
只在副本替换一个 `sirv_expl_axi_slv` 实例，保留所有端口连接。
不改 CPU 数据通路、原 TCM 容量、原平台源码或已经通过的运行目录。
容量不符或外设文件与已核对版本不一致则停止，不自动扩容或放宽检查。

## 程序、模型和内存

模型以 v10 相同的低字优先记录打包，363072 字节，SHA-256：
`a980f9e107d1e0f1272186c618f0b4267f34c5b911a403906c3cbd1a183ffd86`。
每层 30256 字节，前六层放 ITCM，后六层放 DTCM；每次通过 C 回调复制一层到 scratch。

| 存储区 | 地址 | 作用 |
|---|---|---|
| ITCM 代码保留 | 0x80000000–0x80003fff | 启动、应用和实际 C 驱动 |
| ITCM 参数 | 0x80004000 起，181536 字节 | 第 0–5 层参数 |
| DTCM 参数 | 0x90000000 起，181536 字节 | 第 6–11 层参数 |
| DTCM 输入 | 0x90030000，6336 字节 | CPU 从这里取输入 |
| DTCM 输出 | 0x90032000，6336 字节 | CPU 最终写回，TB 逐字节核对 |
| 单层 scratch | 0x90034000，30256 字节 | 参数回调输出 |
| C data/bss | 0x9003b800–0x9003bfff | 链接器限制的静态区域 |
| 栈 | 0x9003c000–0x9003efff | 栈顶 0x9003f000 |
| 完成 mailbox | 0x9003ff00 | 状态、周期及异常原因 |

权威布局为 `sw/e203/layout.json`。生成器检查区域不重叠、ELF32/RISC-V 入口正确、
加载段未覆盖数据缓冲，并记录源码、程序、镜像和参数哈希。
TB 预装测试输入/模型和程序，这与指令测试的 TCM 镜像装载方式一致；
预装本身不计入任务周期，也不证明外部 Flash 或 DMA 装载路径。
输入搬运、参数层复制/写入、计算等待、输出读取及 DTCM 写回全部由 CPU 完成并计时。

`mcycle` 从驱动开始搬运输入前读到最终输出存入 DTCM 后读，包含回调和总线等待。
完成 mailbox 的 magic 在最后写入并用 fence 排序。异常处理器记录 mcause/mepc/mtval，
TB 立即判失败。TB 最后比较的是 CPU 写回的 DTCM 内容。

## 服务器运行

上传包：`kwt_e203_c_driver_20261030.tar.gz`。
包内带预编译 RV32 ELF 和可校验镜像，服务器无需交叉编译器，只需原 EDA 环境和 Python 2.7/3。

```bash
mkdir -p ~/soc/kwt_e203_c_driver_20261030
tar -xzf ~/Desktop/kwt_e203_c_driver_20261030.tar.gz -C ~/soc/kwt_e203_c_driver_20261030
bash ~/soc/kwt_e203_c_driver_20261030/tools/run_e203_kwt.sh
```

先跑 CPU/MMIO 短测试，通过后运行完整十二层。可用 `--suite smoke` 仅检查短路径。
编译最多 15 分钟，每次仿真最多 20 分钟；模拟另有 4000 万外部时钟周期上限。
不执行综合或 hold 修复，不复跑已通过的 v10/v11 测试。
每装载完一层参数输出 `CPU_LAYER_PARAMETERS`；实时日志位置会在终端显示。

完整通过必须同时有：

```text
PASS: E203 CPU boot / C program / ICB-AXI MMIO / input / reset
CPU_TASK inputs=1584 parameter_words=90768 output_words=1584 core_cycles=... peripheral_cycles=... cpu_cycles=... instructions=...
PASS: E203 CPU C driver full encoder / 6336 shared-memory bytes bit-exact
RESULT: PASS (full; actual CPU instruction execution, not timing signoff)
```

`instructions` 为 TB 观察到的 ALU commit valid/ready 握手计数，帮助确认实际指令执行。
核心和外设计时不会等于 v11 总线主机结果，CPU 软件及总线等待会改变加载节奏。
最终仅以回传的实际指标为准。失败时保留首个诊断和隔离目录，不自动绕开原断言。

## 本地重建与检查

编译工具为 [Zig 0.13.0 的 clang/lld](https://ziglang.org/download/)，
本地使用其维护者发布的 [PyPI Windows 分发包](https://pypi.org/project/ziglang/0.13.0/)，
wheel SHA-256 为 `b64b2aa936ebbfeecfbb2611df331a5474edebe1246b98c2f56d6ae4d58b71fc`。
服务器包不含编译器，附带来源和哈希。命令示例：

```bash
python tools/build_e203_kwt_images.py --zig /path/to/zig --out build/full
python tools/build_e203_kwt_images.py --zig /path/to/zig --out build/smoke --smoke
```

也可用 `--cc /path/to/riscv64-unknown-elf-gcc`。较旧 GCC 不认识扩展名时可显式
指定 `--march rv32imac`；生成器默认 `rv32imac_zicsr_zifencei`。
输出目录必须不存在，以免混合旧镜像。
`build.json` 包含实际命令和源码哈希；修改 C/启动源码后必须重新生成两个镜像。

运行器的离线控制流检查：`python tb/test_e203_kwt_tools.py`。
它验证失败检测和原平台不变，使用假的 VCS，不代表 CPU 仿真通过。
