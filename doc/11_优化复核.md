# 优化复核（2026-10-22）

## 已落地

- 点积：64 项串行累加改为六级平衡归约，W4 为 12 位乘积、最终 18 位精确和；W8 为 16 位乘积、最终 22 位精确和。最后加 int32 累加器，保持溢出回绕、一拍延迟和每拍发射能力。实际 PPA 改善待综合，不能宣称 Fmax 已提高。
- GEMM：补全四个流水索引寄存器的异步复位。
- AXI 到计算核：新增 `kwt_axi_top`，实现 packed MFCC 写入到 40→64 stride 输入缓存的并行拆包，接通启动/忙/完成/软复位、预测结果、周期计数和 ACT 读口；参数权重/量化表仍从平台端口加载。
- AXI：修复 MFCC 窗口只译码 64 字而非 980 字的问题；输出索引从带基址改为相对地址，并扩至 11 位覆盖 1584 字；去掉 mfcc_we 的跨 always 多驱动；CTRL 尊重字节使能，软复位清计数；MFCC 无 byte-enable 端口，因此拒绝非零部分写和非对齐写，零 strobe 为无操作。
- 验证：MFCC 测试覆盖全部 980 字，包含地址上界、零/部分字节使能、非对齐地址、CTRL 屏蔽、软复位与激活末字；新增 W4/W8 独立标量参考测试，覆盖边界、随机累加器、32 位回绕、有效信号空隙与复位。
- 回归脚本：支持从仓库根目录调用；检查工具退出码、FAIL/ERROR/MISMATCH 与 PASS 标记；移除按进程名杀死全部 xsim 的行为。

## 复核结论与优先级

1. **最高优先级：合规 SRAM 实现。** 当前并行异步读取数组存在综合展开为寄存器的风险。题目限定单/双端口宏，不可依赖定制多端口宏。应先实现 bank、同步读流水和宽度打包，再用真实宏评估并行度取舍。
2. **最高优先级：平台 SoC 端到端验证。** 本轮新增 AXI 到计算顶层壳及数据路径测试；组委会总线、驱动、参数加载仿真环境仍未接入，参数装载等待也未计入。详见 doc/08、09。
3. **随后：关键路径流水。** 平衡树已实施；requant 乘法、LayerNorm 宽运算与 softmax 单周期除法须通过综合定位，避免仅凭 RTL 猜测盲目改算法。
4. **随后：量化精度。** README 的 96.17% 属于已有实验，不能保证未知统一评测集下降≤2pp。本轮未更改标定、权重和数值算法，未重新运行完整语音准确率实验。

现有 RTL 逐位测试能证明固定向量下的功能，不等于 SoC 集成、SRAM 映射、150 MHz 或 2.25 mm² 已完成。
既有 rtl_verified/tb_verified 为历史快照，本轮未覆盖；当前工作源码位于 rtl/tb。
