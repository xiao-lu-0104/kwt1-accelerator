| 差异 | 截图能够确认的内容 | 对集成的影响 |
|---|---|---|
| config.v | ITCM、DTCM 地址宽度均从 16 改为 18 | 每块由 64 KiB 扩为 256 KiB |
| e203_clkgate.v | 锁存使能+与门改成 GENERIC_CLOCKGATE_RVT | 需要匹配的工艺通用单元/仿真模型 |

| sirv_mrom_top.v | 非 FPGA 分支改用带 CLK 的 ROM1KX32 | 应检查宏读延迟与 ICB 响应是否匹配 |
| tb_top、run.makefile | 增加 FPGA 宏，安装副本额外增加 vcs 宏 | 前者选择行为存储分支，后者在当前 TB 中启用 FSDB 波形代码 |

配置基地址未改，当前映射为 ITCM 0x8000_0000–0x8003_FFFF，
DTCM 0x9000_0000–0x9003_FFFF。二者合计 512 KiB，不能当作一个连续的
512 KiB 数据缓冲。之前“整模型参数能放进 512 KiB”的说法仅是容量相加，
实际还受存储分区、代码与栈占用、访问通路及评测装载接口限制。
当前 348.28 KiB 的全部参数大于单独 DTCM 的 256 KiB；
每层 29.02 KiB，或约 58 KiB 的双层参数缓冲仍能采用分层装载方案。

译码变化把 MULDIV 分支的补零数量从 DECINFO_WIDTH-MULDIV_WIDTH 改为
DECINFO_WIDTH-CSR_WIDTH。本地 e203_defines.v 是本次仅换行差异文件，
核算当前宏为总宽 32、MULDIV 13、CSR 26。新拼接宽 6+13=19，
与 32 位掩码相与时无符号左侧补零，低 13 位保持对齐，当前表达式结果与原式等价。
这是不规范的宽度引用，但不能据此断言 CPU 乘除功能坏掉；保留竞赛版，
后续以 CPU 指令回归和编译位宽检查验证，不在接入 KWT 时顺手修改 CPU 译码。

注意 FPGA 与 FPGA_SOURCE 是不同宏：截图里的前者用于选择平台 RAM/ROM 行为分支，
时钟门控模块检查的则是后者，不能认为定义 FPGA 就自动绕过工艺门控单元。
tb_top 内的 FPGA 定义还可能受编译文件顺序影响，以 run.makefile 的全局定义为准。
安装副本里的小写 vcs 宏在当前 TB 中用于 FSDB 波形，不代表额外处理器配置。

当前 MROM 包装的 ICB 握手仍是原先的零等待透传；如果 ROM1KX32 模型是同步读，
就必须验证响应延迟，不能只凭带 FPGA 宏的行为 ROM 仿真通过宣称宏分支也正确。
需要实际模型与启动回归才能确认，截图本身不足以判定该宏的读时序。

本地检查发现：

- `rtl/kwt_axi_top.v:53` 实例化 `kwt_top`，仍包括输入投影、位置编码及分类头。
- `kwt_axi_slave` 的写入口是 MFCC，参数仍通过独立外部 `rom_*` 和加载端口提供，

## 比赛边界

赛题指南规定研究生硬件输入和输出均为 99×64，前处理/输入投影在计算机端离线完成，
分类头由统一软件评测程序执行。比赛集成顶层宜围绕 `kwt_encoder_12` 构建；
原 `kwt_top` 可保留为额外的整机功能演示，不能混用二者的面积及吞吐统计。

平台提供 512 KiB 共享 SRAM，支持分层参数装载，不要求全模型权重同时驻留，
不增设 DDR 等外部存储控制器。复用 E203、共享 SRAM 和固定总线的面积单列，
新增加速器、接口及内部 SRAM 才计入 2.25 mm²。
每个任务的输入/参数装载、总线等待、E203 调度及最终结果写回都要计时，
此前本地 ROM 测试的约 21.55 ms 不能直接当作 SoC 的最终任务延迟。

## 参数容量：按当前 TB 固定槽位布局计算

依据 `tb/tb_kwt_encoder_12.v` 的 wrom、bmrom、bbrom、lgrom、lbrom、lcrom。
这里计算二进制打包容量，不使用 ASCII `.mem` 文件的磁盘大小。

| 内容 | 每层字节 | 十二层字节 |
|---|---:|---:|
| Q/K/V/O + FFN1/FFN2，49,152 个 int4 | 24,576 | 294,912 |
| 576 项 int32 bias + 576 项 int32 multiplier | 4,608 | 55,296 |
| 两处 LN，各 64 项 int16 gamma + beta | 512 | 6,144 |
| 6 个 32-bit 常量 | 24 | 288 |
| 合计 | 29,720 | 356,640 |

即单层 29.023 KiB，十二层 348.281 KiB。该布局保留 Q/K/V bias 等固定槽位，
省略已知零值或进一步压缩元数据可以缩小存储，但需要同步定义新的传输格式。
模型的 607,308 个参数是完整模型的标量数量，不是 int4 编码后的字节数；
编码器矩阵权重共 589,824 个，另有 bias、LN 参数和量化元数据。

首层 int8 输入和最终 int8 输出各 6,336 字节。仅按总容量相加，如果全部十二层参数及一份输入、
一份输出都驻留共享 SRAM，合计 369,312 字节，512 KiB 中还余 154,976 字节，
但实际竞赛配置已确认是两块各 256 KiB 的 TCM，以上余量不是单块数据区的可用容量；
还须核对代码、栈、跨区访问及其他存储使用。更稳妥的方案是按赛题的分层加载机制，
复用约 29 KiB 的单层共享缓冲；双缓冲参数有效数据约 58 KiB，
缓冲分配对齐、协议头和其他运行数据另计。

加速器现有 80 KiB 内部 SRAM 已含当前层的权重及系数缓存，
不用再增设一份 348 KiB 的加速器私有参数 SRAM。

## 两处集成笔记需要纠正

`E203平台集成笔记.md` 的“合计约 288 KB”只覆盖 int4 矩阵权重，遗漏了元数据。
“参数必须放片外，ASIC 必须新增 AXI master 或 QSPI 控制器”不符合当前赛题的
共享 SRAM/分层装载安排。先实现 CPU 从共享 SRAM 向加速器 MMIO 搬运即可；
DMA 是之后的效率优化选项。

“必须升级完整 burst AXI”也不能仅凭接口名得出结论：当前官方克隆中的
`rtl/e203/general/sirv_gnrl_icbs.v:1142`、`:1143` 把 ARLEN/AWLEN 固定为 0，
`:1159` 把 WLAST 固定为 1。该通路当前只产生单拍请求，
可以先采用明确的单拍 AXI/Lite 适配并正确生成 RLAST，处理地址解码、字节使能、
读写背压及通道顺序；无需为此先做通用多拍 burst 引擎。
正式竞赛版的总线转换器仍须与当前克隆版本比对确认。

参数暂停时不应只冻结扫描地址：必须让参数写使能与有效数据一致，
常量寄存器也只在接收有效数据时更新；共享 SRAM 读延迟、64-bit 数据组装、
最后一次内部 SRAM 写回完成后再启动计算，都需要有明确握手。

## 完成顺序

1. 实现比赛专用 encoder 总线顶层，支持 99×64 输入和最终输出读回。
2. 接通单层参数 MMIO 加载及编码器暂停/继续机制；先做 CPU 搬运，无需新增整模型私有 RAM。
3. 替换正式平台示例从机，加入 C 驱动，运行 CPU 发起的完整十二层任务及连续任务。
4. 接入真实 SRAM 模型，核对完整面积、所有存储相关时序路径及活动覆盖，补齐同配置评测。

README 的“四项硬门槛全部通过”目前应谨慎使用：本地 `syn/dc_compact.tcl`
仍明确采用未解析的 SRAM 黑盒，没有读入宏 `.db`，并用 `catch` 包裹边界延迟设置。
宏面积按官方面积表独立加总符合赛题统计方式，但这不等于宏时序和功耗模型已经接通；
若服务器已有更新脚本及完整宏模型，应将其同步回工程后再冻结结论。
