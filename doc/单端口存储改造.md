# 单端口存储改造：第一批实现

2026-10-31。对应 [架构重整规划](架构重整规划_20261031.md) 的 G0/G1。

## 当前范围

新增 `rtl/kwt_sp_sram_ctrl.v`，保留原编码器与半拍实现作为对照。
新控制器不推断 SRAM，不假设厂商引脚名；物理侧显式输出使能、读写、地址和完整字数据。
真实 RAMSP 引脚/控制值必须从交付包核对后，通过单独绑定层接入。
当前不能将它直接替换进旧 `kwt_mem16`：两者吞吐和握手契约不同。

| 项目 | 本批实现 |
|---|---|
| 访问端口 | 同一上升沿，一个未完成请求，读写共享物理端口 |
| 宽字 | DW 为 16 的整数倍，各 16 位 bank 同步执行一次逻辑请求 |
| 请求接收 | `req_valid && req_ready`；地址、操作、数据与掩码在该拍捕获 |
| 局部写 | 4 位粒度掩码；全掩码直接写，零掩码有序空操作，其余读改写 |
| 读响应 | 宏读边沿后再等一个完整周期捕获数据，允许实际 Tco |
| 写响应 | 在物理写边沿之后返回，不能将进队列误认作写完成 |
| 背压 | 响应未消费时，保持响应数据稳定，不接收新请求、不访问宏 |
| 初始化 | 复位后逐地址写零；完成前不接收用户请求 |
| 显式清空 | `clear_valid/clear_ready`，优先于新请求，但不能越过未消费响应 |
| 排空 | `idle` 表示已初始化、无进行中请求和无待消费响应 |

首版选择顺序清零，避免给每个 SRAM 字增加有效位寄存器，也避免局部写合并到旧任务数据。
这细化了规划中的初始化策略：物理宏本身没有复位；控制器执行真实写事务。
代价为每次清空 DEPTH 个周期，同深度的并行 banks 同时清零，不按总 bank 数串行累加。
以 150 MHz 为例，1024 深度约 6.83 us，4096 深度约 27.31 us；正式任务中的清空开销必须统计。
后续是否改成按需初始化，要用面积与完整任务时间对照决定。

## 局部时序

请求接收后执行完整物理事务，不追求每拍接收：

- 读：接收 → 宏读 → 捕获数据 → 响应。
- 全字写：接收 → 宏写 → 响应。
- 局部写：接收 → 宏读 → 捕获/合并 → 宏写 → 响应。
- 清空：接受清空 → 逐地址宏写零 → initialized/idle。

这是保守的功能协议。真实宏的 setup/hold、周期、脉宽和 Tco 仍须用原模型与 Liberty 检查，
不能据此认为已经满足 150 MHz。原 1R1W pending 流水不沿用到新控制器。

运行中复位取消逻辑请求/响应；此前不可撤销的物理写可能已经发生，随后逐地址清零隔离旧任务。
正常 clear 不取消未完成请求，必须等待 response 消费后才能接受。
对新任务发布 ready 以前，所有初始化写必须完成。

## 本地验证

`tb/tb_kwt_sp_sram_ctrl.v` 用独立参考数组核对：

- 16×128、32×1024、16×4096、128×128 四种逻辑配置。
- 逐 nibble 部分写、零掩码、全掩码、连续 A/B/A 地址及随机写读。
- 响应等待期间数据稳定、禁止新请求与多余宏访问。
- clear 在待消费响应之后执行，清空后逐地址读回零。
- 初始化中再次复位、读改写尚未提交时复位。

测试用 `tb/models/kwt_sp_memory_model.v` 是显式协议替身，内部数组无复位，读延迟 1.25 ns；
不是厂商模型，不含真实时序检查，不能作为 G1 通过的最终证据。
本地 XSIM 2022.2 四种配置已通过，共 7896 次常规记分板请求；
另外执行清空阻塞及中途复位场景。本地记录：`release/sp_ctrl_local_20261031/simulation.log`。

证据提取工具测试：`python tb/test_kwt_sp_foundation_tools.py`。
它验证读取报告不自动生成绑定、错误库单元/电压选择拒绝、旧报告不被覆盖。

## 服务器第一轮

运行入口：`bash tools/run_kwt_sp_foundation.sh`。
脚本新建隔离目录，读取 RAMSP1024X16 原始声明、控制语句、时序检查、TT Liberty 与手册，
记录文件哈希和全部库角路径；随后用 VCS 重跑相同控制器的协议替身测试。
`--audit-only` 可以只提取资料。每阶段有超时，不运行长综合和全局 hold 修复。

需要回传终端末尾及 `audit/summary.txt` 中的引脚声明和手册摘录。
在尚未核对实际引脚、电平、读写含义、EMA/保留模式前，脚本不会猜测绑定。
因此本轮即使协议通过也固定保留：

```text
FOUNDRY_BINDING_STATUS: PENDING_PORT_AND_CONTROL_REVIEW
FOUNDRY_TIMING_STATUS: NOT_RUN
SYNTHESIS_STATUS: NOT_RUN
G1_STATUS: OPEN
```

下一批根据这份证据添加真实 RAMSP 绑定、开启原时序检查的短测试和小综合。
G1 通过后再迁移单层核心及十二层调度，DMA 仍在核心和 CPU PIO 基线之后。
