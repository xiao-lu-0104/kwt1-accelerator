# SoC 参数接口接入：第一步（2026-10-30 v10）

当前开始把独立编码器接到 E203 的实际控制与数据搬运路径。
本步骤完成参数握手和 32→64 位流式拼接，完整 CPU/AXI 集成仍在后续步骤。
服务器上 v8b/v9 已验证的 SRAM/PPA 结果保留在原工作目录，不能当作新 RTL 的综合结果。

## 接入现状

- 竞赛平台在 0x40000000 扩展口已有 ICB→AXI 桥；桥的 AWLEN/ARLEN 固定为 0，
  WLAST 固定为 1，可以先做明确的单拍适配，并正确处理 RLAST、响应及背压。
- `kwt_axi_top` 当前面向 MFCC 输入、投影、编码器和分类头的整机接口。
  其内部 `kwt_top` 已实例化紧凑编码器；问题在于任务边界和参数搬运接口，
  不能简单理解成计算核心仍是旧代实现。
- 赛题编码器任务输入/输出为 99×64，参数采用分层装载；不增加整模型私有 RAM。
- CPU 基线 67/67 通过；当前尚无 CPU 发起完整编码器任务的端到端 PASS。

## 本步骤实现

`kwt_encoder_12` 增加 `PARAM_HANDSHAKE` 参数和 `param_valid/param_ready` 端口。
默认 `PARAM_HANDSHAKE=0` 保留组合 ROM 接口。设为 1 后，只在两信号同时为 1 的
上升沿接收参数；扫描地址、参数 SRAM 写使能、LN 和六项常量寄存器均遵守握手。
等待周期仍计入 `cycle_count`，不会停住整颗芯片的时钟。

`kwt_param_stream` 把两个 32-bit 数据传输拼成一条 64-bit 记录，先低字后高字。
它保留输出直到被编码器接受，复位丢弃完整及半写记录，适合后续接 MMIO 写握手。
当前没有把它直接接到旧 AXI 壳，以免混用 MFCC 与编码器任务接口。

### 每层记录格式

| 类型 | 扫描选择/地址 | 条数 | 64-bit 数据 |
|---|---|---:|---|
| Q/K/V/O、FFN1/2 权重 | sel 0..5；地址每次 +16 | 3072 | 最低 nibble 是第一项，共 16 个 int4 |
| bias / multiplier | sel 6..9 | 576 | `[31:0]` bias，`[63:32]` multiplier |
| LN1 / LN2 | sel 10，地址 0..127 | 128 | `[15:0]` gamma，`[31:16]` beta，其余填 0 |
| 六个常量 | sel 12，地址 0..5 | 6 | `[63:32]` 常量，低字填 0 |
| 合计 |  | 3782 | 7564 个 32-bit 传输，30256 bytes |

原有效参数每层 29720 bytes。固定 64-bit 记录为 LN/常量增加 536 bytes 填充，
单层 CPU 缓冲约 29.55 KiB，十二层记录共 363072 bytes。仍按层复用共享缓冲，
不要求把全部参数放在单块 256 KiB DTCM 中。

`tools/pack_kwt_param_stream.py` 直接打包已有黄金参数向量，不改变数值、校准或量化。
输出 little-endian `.bin`、按低/高 32-bit 字顺序的 `.mem` 和元数据/SHA256。

## 发现并修正的长度问题

原 `wlen()` 返回 14 位，而 FFN 的长度为 16384，需要至少 15 位。
长度截为 0 后，与 16-bit 计数器比较的结束值变成 65520；14-bit 地址绕回，
每个 FFN 参数块因此扫描四遍。相同参数被重复写入，旧数值回归仍然可以通过。

现将长度返回值和常量切片扩为 16 位，地址宽度不变。
短测试确认每层恰好接收 3782 条记录，而非原来的 9926 条。
十二层预计减少 `(9926−3782)×12 = 73728` 拍：原冻结基线 3232909 拍，
新无等待版本预期 3159181 拍；完整输出及周期必须以服务器回归确认。

## 验证状态

本地 XSIM 配合明确标注的 SRAM 替身已通过：

- 参数流 256 条记录的顺序、随机背压、输出保持和半条记录复位。
- 真实编码器的所有参数选择、地址、写使能、常量、加载中复位和最终启动条件。
  默认模式每层 3782 条，握手模式同样 3782 条并经历 8405 个等待周期。
- 恢复旧长度截断、强制忽略 valid 的两个错误对照均被测试拒绝。
- 十二层参数逐项解包校验：全部权重、bias/m、LN 和常量与原 `.mem` 完全一致。
- 运行脚本对编译错误、时序诊断、缺少 PASS、错误周期、未施加等待及流未读完均报失败。

这些是本地测试。服务器真实宏的完整默认/流式计算回归尚待运行。
带等待的完整测试会把无效输入设为 X，比较全部 6336 输出，并检查：
共 45384 条参数记录、90768 次 32-bit 传输、总周期等于 3159181 加实际等待周期。

## 服务器回归

新包 `kwt_param_handshake_20261030.tar.gz` 包含新 RTL、测试、黄金向量及打包工具，
不包含工艺模型、库、旧网表或旧综合检查点。执行：

```bash
mkdir -p ~/soc/kwt_param_handshake_20261030
tar -xzf ~/Desktop/kwt_param_handshake_20261030.tar.gz -C ~/soc/kwt_param_handshake_20261030
bash ~/soc/kwt_param_handshake_20261030/tools/run_kwt_sram_binding.sh --param-handshake
```

本命令运行七组功能测试，不执行综合或 hold 修复。宏时钟短测开启 specify，
其他测试是无 SDF 的理想 RTL 功能验证。所有结果记录在新的隔离工作目录。
看到 `BINDING_REVISION: 20261030_v10_parameter_handshake` 才是本步骤的新包。

## 后续接入顺序

1. 在新的 encoder MMIO 顶层接入输入写入、参数流、启动/忙/完成和输出读取。
2. 做单拍 AXI 适配及 C 驱动，测试通道先后顺序、背压、错误响应和连续任务。
3. 在正式 E203 平台的隔离副本替换示例外设，运行 CPU 发起的完整十二层任务。
4. 从首次输入/参数装载到最终结果写回统计周期，补完整顶层的面积、时序和活动功耗。
