# 加速器架构方案（决策稿）

> 历史草案提示（2026-10-27）：本文的工艺面积与带宽是早期估计，不能用于判断面积达标。
> 当前默认实现与实测见 [14_紧凑架构与优化结果](14_紧凑架构与优化结果.md)。
> 内部 SRAM 必须按指定 16-bit 宏拼接并取整；原文“面积非常宽松”等判断尚无工艺库支持。

> 状态：v0.1 草案，待队内确认
> 依据：赛题硬约束 + 已完成的数值实验

## 1. 硬约束回顾

| 项 | 要求 |
|---|---|
| 时钟 | 150 MHz |
| 面积 | 加速器 + 接口 + 内部 SRAM ≤ 2.25 mm² |
| 精度 | Top-1 相对浮点下降 ≤ 2 pp |
| 共享 SRAM | 512 KB，不设 DDR |
| 内部 SRAM | 只能用 16b×128 / 16b×1024 / 16b×4096 宏 |
| 计时 | 输入+参数装载 → 结果写回，全部计入 |
| 缓存 | 任务前清空数据与参数缓存 |
| 接入 | System Bus 或 NICE，二选一 |

## 2. 计算量分解

| 算子 | 每层 MAC | 12 层 |
|---|---|---|
| QKV 投影 | 3 × 99×64×64 = 1.22 M | 14.6 M |
| QKᵀ | 99×99×64 = 0.63 M | 7.5 M |
| AV | 99×99×64 = 0.63 M | 7.5 M |
| O 投影 | 99×64×64 = 0.41 M | 4.9 M |
| FFN1 | 99×64×256 = 1.62 M | 19.5 M |
| FFN2 | 99×256×64 = 1.62 M | 19.5 M |
| **合计** | **6.12 M** | **73.4 M** |

## 3. 并行度选择（纯计算，不含装载）

| MAC 阵列 | 理想周期 | @150 MHz | 若 +30% 控制开销 | 面积粗估（28nm） |
|---|---|---|---|---|
| 64 | 1.15 M | 7.6 ms | 9.9 ms | ~0.08 mm² |
| 128 | 573 K | 3.8 ms | 5.0 ms | ~0.15 mm² |
| **256** | **287 K** | **1.9 ms** | **2.5 ms** | **~0.30 mm²** |

> 面积上限 2.25 mm² 非常宽松（SRAM 宏约 0.03 mm²/32 KB）。**吞吐与面积不是主要矛盾，工程完成度才是。**

## 4. 参数装载 — 真正的瓶颈

| 格式 | 全量 | 走 E203 load/store（效率~25%） | 走 DMA（效率~80%） |
|---|---|---|---|
| W8 594 KB | 594 KB | ≈ 4.0 ms | ≈ 1.2 ms |
| W4 300 KB | 300 KB | ≈ 2.0 ms | ≈ 0.6 ms |

结论：
1. **必须做 DMA**，否则装载时间超过计算时间。
2. 若能一次把 12 层全留在片上（W4 可行），可省掉中间层重装。

## 5. 存储组织（方案 A：W8，保守）

```
共享 SRAM 512KB
  ├─ 参数区：12 层 × 49.5KB = 594KB  → 超了，必须分批
  └─ 数据区：输入/输出

片上 SRAM（16b×4096 × N）
  ├─ x 缓冲     99×64 int8   = 6.3 KB
  ├─ Q/K/V      3×99×64      = 19 KB
  ├─ score 行    99×int16    = 0.2 KB
  ├─ attn ctx   99×64        = 6.3 KB
  ├─ FFN 中间   99×256       = 25 KB
  └─ 权重双缓冲 2×49.5KB     = 99 KB
```
片上约 156 KB → 20 个 8KB 宏，面积 ~0.2 mm²。可行但偏大。

## 6. 存储组织（方案 B：W4 权重，激进）

```
共享 SRAM 512KB
  └─ 全部 12 层权重一次驻留：300 KB  ✅ 剩余 212 KB 给数据

片上 SRAM
  ├─ 激活缓冲（复用）  ~32 KB
  └─ 权重预取双缓冲   2×25KB = 50 KB
```
优点：参数只装一次，装载开销最小；缺点：int4 解包逻辑 + per-group scale。

## 7. 两种接入方式对比

| | System Bus (AXI) | NICE |
|---|---|---|
| 数据搬运 | ✅ 可做 DMA master，批量 | ❌ 依赖 CPU load/store |
| 控制 | 寄存器映射 | 自定义指令 |
| 实现复杂度 | 中（需握手/仲裁） | 低（但数据通路受限） |
| 适配平台工程 | 平台若已有 AXI 互连则简单 | 需改 CPU 核或 NICE 接口 |
| **建议** | **✅ 首选** | 仅当平台强制 |

> 关键理由：每任务要搬 300–600 KB 参数，NICE 的指令级接口无法胜任。

## 8. 数据流（层内，行级流式）

```
for token_i in 0..98:
    q_i = x_i · Wq            (64 MAC)
    score_i = q_i · K^T       (99×64)
    p_i = softmax(score_i)    (99)
    ctx_i = p_i · V           (99×64)
    o_i = ctx_i · Wo + bo     (64)
    x1_i = LN1(x_i + o_i)     (64)
    h_i = GELU(x1_i · W1 + b1) (256)
    f_i = h_i · W2 + b2       (64)
    out_i = LN2(x1_i + f_i)   (64)

每层需要：K, V 全量（99×64×2）；x 全量（99×64）；其余按行
```
- K/V 需先算完并驻留 → 12.4 KB (int8)
- 行内 score 只需 99×int16 = 198 B
- **FFN 的 256 维中间结果按行算完即用**，不必存整层 → 省 25 KB

这是最省 SRAM 的组织方式。

## 9. 建议配置（待决策）

| 项 | 建议值 | 理由 |
|---|---|---|
| 接入 | System Bus + DMA master | 搬运量决定 |
| 权重 | W8 per-channel（先），W4 作为优化项 | 先保精度，再压带宽 |
| 激活 | int8 per-tensor | 实验零损失 |
| softmax 概率 | int8 独立 scale（absmax≈0.17） | 实验验证足够 |
| MAC | 256（4×64） | 面积充裕，吞吐 2.5ms |
| 内部 SRAM | 32–64 KB | 行级流式 |
| 残差对齐 | int16 累加后统一 requant | int8 直接相加误差大 |
