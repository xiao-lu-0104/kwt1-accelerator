## 主要问题（按重要性）

### 1. [P1] “标准单元连通、可定版”与其自身表格矛盾

原报告第20、23、149、254、270行。

v6仍报告VDD浮空标准单元6个、VSS浮空63个，以及浮空线15302/19695。两网计数可能指向部分相同实例，不能直接相加当成69个独立单元，但显然不能写所有标准单元已连通。数量小不证明是可忽略单元，需要列出实例、ref、PG pin、用途、应供电网络和实际物理路径。

宏浮空0/0是有价值的改善，但还要确认检查范围、逻辑网名绑定和宏VDDPE/VDDCE/VSSE各供电脚的覆盖，以及电源网络接到预期顶层供电入口。宏归入已连接网络不等于完成IR/EM或外部供电验证。

建议将“定版PG”改为“v6实验候选，连接及DRC整改未完成”。若用户只要可视化，可在明确标记未通过的独立副本继续后续几何流程；这与认定PG合格不同。

### 2. [P1] 残余DRC与M4规则没有获得豁免依据

原报告第23、145、149、267～270行。

“同网”“PG自身金属”“宏库内部”都不能自动消除DRC的含义。报告自行写“记waiver、不阻塞”尚缺适用规则、对象、范围、可验证原因和项目接受依据。不能因为用错误间距能接通、换一种via后断开，就认定必须保留非法间距。

M4形状长度等于宏高度，只能支持“可能属于宏引脚”；不足以单独证明两个对象都来自未经修改的原始宏、满足实际宏尺寸/方向转换、没有用户PG/via landing或OBS参与，也不足以证明只有修改工艺库才能解决。需记录每条错误的两对象来源、ref/pin/层、bbox、规则，并在无用户PG的原始宏参考/诊断副本中复现同一检查条件。若确认参考抽象与技术规则不一致，应核库与层栈/规则版本组合，不直接改PDK或将776条一律豁免。

厂商T-2022.03设计规划指南把同网via cut间距不足列为实际DRC示例，并分别解释PG检查与连通检查。这支持“同网仍需查规则”的判断，不代表某一条当前工程错误已被厂商判定。[Synopsys《IC Compiler II Design Planning User Guide》公开托管副本，Checking Power Network Integrity](https://www.scribd.com/document/939978599/IC-Compiler-II-Design-Planning-User-Guide)。实际选项仍以安装版man为准。

### 3. [P2] via根因论证超出样本能证明的范围

原报告第85～91、99～102、122、145行。

两个via cut同属VDD、相距0.055，只证明这两个同网cut触发所述规则，不能确定它们属于同一个via阵列。也可能是两个独立via、不同策略或与库中既有via的相互作用；需via master/实例或父对象/来源策略来区分。

ring+mesh与“加入1×1 rails”结果相同，只能说明这一次新增的1×1 rails没有增加这些错误。它不能替原先default rails洗脱所有责任；default→1×1本身就是关键变量。特别是首版有72606而分段实验只有17458，其他错误从何而来仍需同条件分段归因。

v7存在清除dangling/floating对象的日志，不足以证明一定是“孔先因DRC非法删除→M1轨随之清除”。需清除前后的对象数、via实际生成数、命中的策略规则和删除原因；也应排除没有匹配到既有strap、via master/落点/包围要求不符等可能。不能由一次1×1方案失败推断合法的1×1/其他连接方案都不可行。

### 4. [P2] M1最小线宽与pitch混淆，宽度因果没有证明

原报告第143行。

已存原生层记录的摘要是M1 pitch0.14、min_width0.07、min_spacing0.07，见工程`Doc/ICC2完整实现进度_20261109.md`第16行。报告引用“最小线宽0.14”与此不符，疑似把pitch当作min_width；1110若使用不同技术库，必须给出它实际的原生属性证据后再比较。

即使最小宽度真是0.14，0.2大于最小宽度也不能直接解释间距违规。要给出两条轨/PG pin的坐标、行间距、宽度和净间隙，判断是否宽度扩张导致冲突。v4失败最多支持所试的双层0.2配置不适用，不证明所有手动rail_width都不可用。

### 5. [P2] v6统计分解不能对账，摘要的“全部M1/V1”不准确

原报告第23、241、242、267行。

- v5表格分项20889+10361+776=32026，与标出的32042相差16。
- v6写V1约1.7万、M1约3千，加M4的776只有约20776，距28006差约7230，不能充当28,006项的完整分类。
- 摘要称全部为M1/V1间距，与后文保留M4的776矛盾。
- 首版六项分类相加确为72606，这部分算术没有发现问题。

需要从同一份v6原始报告自动汇总error type×layer×rule，分项严格合计28006，再判断是否仍有overlap/其他short等类别。表中“M2 short=0”本身不能代替所有层short=0的完整证明。

### 6. [P2] 不能将本次错误集API失败写成工具普遍限制

原报告第58～60行。

当前会话查询错误集得到0，只证明该次查询没取到对象，不足以得出“裸跑check_pg_drc永远不生成可查询错误集”。T-2022.03-SP1指南说明默认可生成供GUI Error Browser查看的数据，-no_gui用于跳过，-output是文本输出；用户的SP2-1版本仍需以安装版手册和实际会话为准。

建议保留已成功的`check_pg_drc -output`文本采集方法，将结论改为“本次API流程未取得可查询错误对象，暂采用文本输出”，另记会话、block、check执行方式和数据存储/打开步骤，不永久禁止未经查明的接口。
