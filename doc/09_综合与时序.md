# 综合与时序：当前状态与实现约束

当前尚无有效的标准单元面积、150 MHz 时序收敛或功耗结果。
已有 Vivado 脚本用于 FPGA 原型检查；不能把 Artix-7 资源换算成可信 ASIC mm²。
Vivado 的器件选择流程也不能仅替换成 read_liberty/compile_ultra 即成为 ASIC 流程，
后者需要对应综合工具、工艺库、SRAM 封装和 SDC 脚本。

## 存储是当前主要实现阻塞

赛题指定内部存储为 16 bits×128/1024/4096 单端口或双端口 SRAM 宏。
因此原先建议的定制 64 读口 SRAM 不符合给定条件。
当前 GEMM 使用异步多地址数组读取，Vivado 曾报告 RAM dissolved into registers；
不能据此声称宏映射已完成，也不能以 SRAM bitcell 面积估计替代宏和外围电路面积。

优先采用按数据通道分 bank 的实现：

- 激活按 64 个输入 lane 分 bank，同一拍每 bank 读一个元素，四个输出通道广播复用。
- 权重按四个输出通道和 64 个输入 lane 分 bank，每拍需要 256 个 nibble。
- 16 位宏可以打包多个元素；需结合权重布局、宽写入、bank 冲突和宏利用率设计。
- 宏读口通常有同步延迟，需要显式增加读请求/数据有效流水及配套地址标签。
- bank 数过多时应比较减少并行度、权重复用与阵列分时方案；吞吐变化应由实测周期确定。

这可以用单/双端口宏构建带宽，但有宏最小深度导致的容量浪费；
本轮没有把现有数组伪装成已经完成的 SRAM 实现。

## 本轮已实施的逻辑优化

kwt_dot64 改为六级平衡加法树，乘积和各级求和使用足够的精确位宽，
最后与 int32 累加器相加，保持原有 32 位回绕语义和一拍输出延迟。
它减少 RTL 描述的串行加法深度；实际面积、时序和功耗收益仍须综合确认。
GEMM 发射和输出索引寄存器补齐异步复位，消除复位分支缺失导致的实现风险。

## 服务器验证清单

1. 建立合规的 SRAM bank 封装，逐位仿真后再综合；确认无巨型寄存器阵列替代宏。
2. 用平台参数装载接口取代零等待 ROM 假设，计入总线等待与 E203 调度。
3. 冻结同一配置，约束 150 MHz，覆盖输入/输出延迟、时钟不确定性、宏时序。
4. 检查点积、requant 乘法、LayerNorm 宽乘法、softmax 组合除法的真实关键路径。
5. 在完整计时窗口采集活动，统计加速器、E203、互连和 SRAM 功耗与能耗。

现有 1,477,755 周期是已有 TB 激励条件下的仿真值，不是含真实平台总线等待、
CPU 调度及完整输入装载的竞赛吞吐成绩。不得据此宣称面积/时序/能耗达标。
