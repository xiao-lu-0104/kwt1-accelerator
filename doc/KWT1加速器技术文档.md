## 1. 项目概述

用 ARM Keyword Transformer（KWT-1）开源预训练权重，在 RISC-V SoC 平台上实现
数字前端加速器，完成端侧离线语音指令识别。

| 项 | 内容 |
|---|---|
| 输入 | 1 s / 16 kHz 单声道语音 → 98×40 MFCC → 投影 + class token + 位置编码 → 99×64 |
| 模型 | 12 层 PostNorm 编码器，d_model=64，1 注意力头，FFN 64→256→64，GELU(erf)，607,308 参数 |
| 输出 | 12 类关键词 |
| 权重来源 | `ARM-software/keyword-transformer` @ `237e4097`，`models_data_v2_12_labels/kwt1/best_weights` |

### 赛题硬约束

| 项 | 要求 |
|---|---|
| RTL | Verilog / SystemVerilog，可综合；不含布局布线 |
| 模型 | 不得重训/微调/蒸馏，不改层数、维度、运算结构；允许无梯度标定与数值转换 |
| 数值 | 自由选择定点/浮点/位宽/舍入/MAC 结构/并行度/非线性近似 |
| **面积** | **≤ 2.25 mm²**（1.5×1.5），含加速器 + 接口逻辑 + 内部 SRAM 宏 |
| **内部存储** | **只能用 16b×128 / 16b×1024 / 16b×4096 宏，单口或双口** |
| 时钟 | 150 MHz，SoC 提供 PLL |
| 精度 | 研究生：Top-1 相对浮点参考下降 **≤ 2 pp** |
| RTL 一致性 | **必须与提交的软件数值模型逐位一致** |

### 计分与门槛

| 项目 | 研究生（100 分） |
|---|---:|
| 功能与数值精度 | 35（注意力 10 / 单层 10 / 十二层调度 5 / 分类精度 10） |
| SoC 集成、综合与复现 | 20 |
| 吞吐量 | 12 |
| 功耗与单任务能耗 | 12 |
| 加速器面积 | 6 |

> **只有通过全部必做功能 + 精度门槛 + RTL 对照 + 时序 + 面积的设计，
> 才进入效率/创新评分。**

### 性能测量规则

- 研究生 1 个任务 = 1 次十二层编码器计算并写回
- 计时**从输入与参数开始装载**到结果全部写回；**任务前清空数据与参数缓存**
- **参数装载、总线等待、E203 调度时间全部计入**；任务间复位不计入

## 2. 数值方案

### 2.1 数据格式

| 张量 | 格式 | scale |
|---|---|---|
| 权重 | **int4**，对称，per-output-channel，`[-7,7]` | `S_w[c] = absmax(w[:,c])/7` |
| 激活 `q_x` | int8 对称，`[-127,127]` | 全局 0.1086 |
| Q / K / V | int8，**各自独立** | 0.0249 / 0.0790 / 0.0358 |
| score | int16 | 1/256 |
| softmax 概率 | uint8 `[0,127]` | 1/127 |
| ctx | int8 | 0.0340 |
| o（O 投影） | int8 | 0.0248 |
| 残差 r1/r2 | **int16**，Q10 定点对齐 | min(两侧 scale) |
| LN 输出 | int8 | 0.0418 |
| GELU 输入 / 输出 | int8，**分开标定** | 0.0430 / 0.0347 |
| f（FFN2 输出） | int8 | 0.0401 |
| block 输出 | int8 | 0.0448 |

### 2.2 矩阵乘 + requant

```
acc[c]   = Σ_i q_x[i] · q_w[i,c]                    (int32)
acc_b    = acc[c] + b_q[c]                          (int32 饱和)
M_int[c] = round(S_x·S_w[c]/S_y · 2^31)             (Q1.31)
q_y[c]   = sat8( (acc_b·M_int[c] + (1<<30)) >> 31 ) (round half up)
```

最坏 `64×127×7 = 56,896`，远小于 `2^31`，累加不溢出。

### 2.3 非线性

| 算子 | 实现 |
|---|---|
| LayerNorm | `rsqrt` 用 256 项 LUT 取初值 + **3 次牛顿迭代**（Q16.16，`y = y(3−vy²)/2`） |
| GELU | 256 项 LUT + 线性插值，`x∈[-6,6]`；`\|x\|>6` 时饱和。**必须按 erf 精确版生成，不是 tanh 近似** |
| Softmax | max 相减 → 256 项 EXP LUT → 求和 → 27 拍串行除法 `(127<<20)/sum` |

### 2.4 精度实测（600 条 validation）

| 模型 | 准确率 | 相对浮点 |
|---|---:|---:|
| 浮点参考（官方 TF） | 97.33% | — |
| **完整定点 12 层** | **96.67%** | **−0.67 pp** |

**门槛 2 pp，余量 1.33 pp。**

消融验证（60 条）：`float / w4 / x8 / qkv8 / score16 / prob8 / ctx8 / o8 / ln8 / h8 / f8 / all`
全部为 96.67%，说明量化策略本身没有额外损失。

### 2.5 实现中修复的 5 个数值坑

| # | 问题 | 影响 | 修复 |
|---|---|---|---|
| 1 | softmax 向下取整 | 99 个概率总和只有 88.7/127（损失 30%） | 改四舍五入 `(e·inv + 2^19)>>20` |
| 2 | GELU 输入输出共用 scale | 输入侧大量饱和 | `hin` 与 `h` 分别标定 |
| 3 | 残差对齐用整数比例 | `s_x/s_o=4.39` 被 round 成 4，少 9% | Q10 定点乘 `(a·ma+b·mb)>>10` |
| 4 | **层间输入 scale 不一致** | 第 2 层起残差放大 2.4 倍，**58.5% → 96.5%** | 每层传入自己的 `s_in` |
| 5 | Q/K/V 共用 scale | Q 只剩 22 个量化级 | 三者独立标定 |

## 3. 架构

### 3.1 演进历程

| 代 | 结构 | 单层周期 | 有效 MAC 利用率 | 问题 |
|---|---|---:|---:|---|
| **Gen1**（直译） | 每算子一份硬件：8 套 GEMM 引擎 + 2 套输入/分类头 = 2048 路 MAC | — | — | 1.47M 触发器，估算 7 mm²，超预算 3 倍 |
| **Gen2 V1** | 共享 64 路 MAC，逐 token 处理 | 542,124 | 17.6% | 控制开销占 82% |
| **Gen2 V2** | MAC 流水重叠 + K/V 合并 | 241,956 | 39.5% | 时序不收敛（−20.4 ns） |
| **Gen3（当前）** | + LN 全路径流水 + 四路 Softmax | **253,143** | **37.8%** | 内部时序收敛（+0.712 ns） |

Gen1 的致命问题是**没有做内存生命周期管理**：算法里每产生一个中间张量就开一个
`reg` 数组（`h_buf` 25 KB、`score_buf` 19.8 KB、`r1/r2_buf` 各 12.7 KB），
1,471,848 个触发器占面积的 75%。现代做法应当做"缓冲分配"——这些张量生命周期
错开，只需两三块 buffer 轮转。Gen2 起改为**行处理**：逐 token 推进，
中间结果全部落行缓存。

### 3.2 当前数据流（单层，逐 token）

```
对每个 token:
  x → attention → o
  r1 = align(x, o) → LN1 → x1
  h  = GELU(F1·x1 + b1)
  f  = F2·h + b2
  r2 = align(x1, f) → LN2 → out
```

K/V 是跨 token 复用的，先整体算好存入 SRAM；其余全部按行处理。

**不再保存**整张 Q、score、概率、ctx、O、FFN 中间矩阵或两张 int16 残差矩阵。

### 3.3 计算单元

`kwt_mac16x4`：**4 输出 × 16 输入**共享点积单元，64 个 int8 乘法器。
W4 权重符号扩展后走 int8，精确 6 级树形归约，int32 模运算累加。

每 group（4 个输出）的周期：`segments × 3 + 8`，其中 `segments = IN_DIM/16`。

### 3.4 存储组织（宏合规）

| 对象 | 宏规格 | 数量 | 容量 |
|---|---|---:|---:|
| 本层 W4 权重 | 16×1024 | 16 | 32 KiB |
| bias / multiplier | 16×1024 | 4 | 8 KiB |
| 输入激活 | 16×1024 | 8 | 16 KiB |
| **合并 K/V** | 16×1024 | **8** | 16 KiB |
| 层间传递 | 16×4096 | 1 | 8 KiB |
| **合计** | | **37** | **80 KiB** |

**K/V 合并**利用了阶段互斥：score 只读 K、AV 只读 V，两者合到一块 `128×1024`。

| 区域 | 字地址 | 布局 |
|---|---|---|
| K | 0–395 | token×4 + 输入维分段 |
| V | 396–907 | 396 + channel×8 + token 分段 |
| 未用 | 908–1023 | 保留 |

V 的 token 维补到 128，超出 99 的位置在 MAC 输入端置零。

`kwt_mem16` 是 16-bit 宏适配边界（DEPTH=128/1024/4096），`kwt_packed_sram`
用多个宏拼接宽字，不依赖 nibble/byte 写掩码——局部写用读改写实现，相邻同址写
用转发。**读改写需要一读一写，所以必须用双端口宏，不能绑单口。**

> **真实 ASIC 综合必须定义 `KWT_ASIC_SRAM` 并提供 `kwt_foundry_sram16` 适配模块**，
> 把 `.clk/.we/.wa/.wd/.ra/.rd` 接到实际宏。目前没有工艺宏库，**尚未完成绑定，
> 不能宣称 ASIC SRAM 映射或面积达标**。

### 3.5 时序流水

Gen2 的三个组合长链（全部在一拍内完成）：

| 路径 | 内容 | 原延迟 |
|---|---|---:|
| Newton 迭代 | 3 个乘法串联 | ~20 ns |
| LN 输出 | 读→减均值→×inv→×gamma→+beta→饱和 | 20.9 ns（31 级） |
| 方差统计 | 4 个并行乘法 + 加法树 | 14.2 ns |

**处理方式**：全部改成分级寄存的流水。

- Newton：4 级流水，每级一个乘法（`y0sq → vy → t3 → y1`），仍执行 3 次迭代，
  保留每步低 64 位截断
- LN 输出：`kwt_mul_pipe`（16-bit 分块乘积、对角线归并、分段进位，6 级流水，
  吞吐每拍一次），地址/gamma/beta/末元素标志与 valid 同步传递，行末 drain
- 方差：拆成读、减均值、平方、两层归并、累加
- MAC：输入、乘积、加法树、反馈累加分级寄存
- 其余：参数 SRAM 返回、bias 相加、requant 乘法、舍入、饱和、GELU 分级寄存

**代价**：每个算子收尾时的排空周期。单层周期从 241,956 涨到 253,143（+4.6%）。

### 3.6 四路 Softmax

`SOFTMAX_LANES=4`（默认）/ `1`（串行对照）。不是四行并行，而是**一行内每拍处理
4 个元素**：score 与 exp 按元素下标低两位分 4 个 bank，最大值/exp LUT/求和分级寄存，
保留一套 27 拍串行除法器。输出四字节 + 四位 mask，99 元素最后一组只写 3 字节。

| 指标 | 串行 | 四路 |
|---|---:|---:|
| 单行 Softmax 本体 | 328 拍 | **117 拍** |
| score + Softmax 阶段 | 74,646 | **53,757** |
| 单层周期 | 274,032 | **253,143** |

每层省 20,889 拍（7.62%），两者 MAC 发射数和逐位输出完全一致。

## 5. 性能与资源

### 5.1 周期

| 粒度 | 周期 | @150 MHz | 有效 MAC 利用率 |
|---|---:|---:|---:|
| 单层 | 253,143 | 1.688 ms | 37.779% |
| 十二层（含参数扫描 + 层间搬运） | 3,232,909 | 21.553 ms | 35.498% |
| 整机（MFCC → 分类） | 3,247,169 | 21.648 ms | — |

**有效利用率口径**：`有效 MAC / (64 × 测量窗口周期数)`，
每层有效 MAC = `4×99×64×64 + 2×99×64×256 + 2×99×99×64 = 6,120,576`。

> **注意**：以上是周期换算值。**实际平台总线等待、参数装载和 E203 调度尚未计入。**
> 权重每层 32 KiB，12 层共 384 KiB；按 128 bit/拍装载约 31.5K 拍（0.21 ms），
> 相对总周期 < 2%。

### 5.3 时序

| 模式 | WNS | 说明 |
|---|---:|---|
| 带 FPGA 引脚（完整报告） | **−1.924 ns** | 最差路径 `u_enc/out_we_reg → out_we`，主要是 OBUF 延迟 |
| **寄存器间（内部）** | **+0.712 ns** | 收敛 |

## 6. 接口（AXI4-Lite）

`rtl/kwt_axi_slave.v` 把加速器包装成 AXI4-Lite 从设备，32 位数据，可挂 E203。

| 偏移 | 名称 | 访问 | 说明 |
|---|---|---|---|
| `0x000` | `CTRL` | W | bit0 `start`（自清零）；bit1 `soft_rst` |
| `0x004` | `STATUS` | R | bit0 `busy`；bit1 `done` |
| `0x008` | `PRED` | R | `[3:0]` 分类结果 |
| `0x00C` | `CYCLES` | R | 周期数 |
| `0x010` | `NFRAMES` | R | 已写 MFCC 字数 |
| `0x100 + 4i` | `MFCC` | W | MFCC 写入窗口，`i = 0..979` |
| `0x800 + 4i` | `ACT` | R | 激活读回，`i = 0..1583` |

**软件流程**：软复位 → 写 980 个 MFCC 字 → 写 `CTRL.start` → 轮询 `STATUS.done` → 读 `PRED`。

MFCC 一字承载 4 字节（小端），`byte_addr = frame*40 + coef`，
按 40 字节 → 64 字节 token stride 映射。仅支持对齐全字写，部分字节写返回 SLVERR。

> 这是加速器接口集成壳，**不是完整 E203 SoC 集成**。patch、class/position、
> 分类头参数与编码器参数 ROM 仍由平台侧提供。

## 7. 复现指南

```powershell
# 数值模型与向量
python tools/fixed_encoder.py            # 600 条端到端定点精度
python tools/calibrate.py                # 生成 scales.json

# 仿真
./sim/run_compact.ps1                    # 默认：单层 + 十二层逐位回归
./sim/run_compact.ps1 -Compare           # A/B/C 配置对照
./sim/run_compact.ps1 -CompareSoftmax    # 串行 vs 四路 Softmax
./sim/run_compact.ps1 -IncludeTop        # 加整机三样本
./sim/run_nonlinear.ps1                  # 非线性算子局部回归
./sim/run_all.ps1                        # 旧后端全量回归

# 综合
vivado -mode batch -source syn/run_compact.tcl                    # 默认（四路）
vivado -mode batch -source syn/run_compact.tcl -tclargs -serial-softmax
vivado -mode batch -source syn/run_compact.tcl -tclargs -ooc      # 模块边界
```

全部通过时输出 `All compact checks passed.` / `All nonlinear checks passed.`。

**VCS 流程**（EDA 服务器）：

```bash
vcs -full64 -sverilog -timescale=1ns/1ps -o simv_top rtl/*.v tb/tb_kwt_top.v
cd sim && ../simv_top      # tb 用 vectors/... 相对路径，必须在 sim 下跑
```

完整环境说明见 `doc/13_EDA平台环境记录.md`。
