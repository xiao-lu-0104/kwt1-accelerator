固定前端提交 `707cd7f4a0a4d416d11bac71112980079e0a9d34`，顶层 `e203_cpu_top`，56 个私有 SRAM 和 64 个共享 SRAM。

从本轮成功 `tpusoc_initial_pr_v2_20261110_707cd7f_*` 的初始布局副本开始，复用其已验证的分组 IO 坐标与位序。重新生成 PG、构建并布线时钟树、执行信号布线、导出并生成检查报告。输入网表、SDC、参考 NDM、初始布局原件均记录指纹。

输入选择核本轮初始包 SHA、source_commit、candidate.v/SDC 指纹、分组 IO 验收状态。只复用已审核 RC TYP 与原始宏物理身份清单的数据文件，不导入此前 PG 实验的设计库。

## 执行方法与时间预算

| 阶段 | 实际动作 | 计划分钟 |
|---|---|---:|
| 01_rc | 绑定 TYP RC、固定宏、1.12 um keepout、标准单元合法化 | 10 |
| 02_pg_basic | 新建电源环、稀疏网格、M1 rails、宏连接，并逐段保存 | 20 |
| 04_build_clock | clock_opt -from build_clock -to build_clock，保存 | 30 |
| 04_route_clock | clock_opt -from route_clock -to route_clock，传播时钟并保存 | 30 |
| 05_route | route_auto，若安装版支持则最多 3 轮详细布线迭代，保存 | 60 |
| 07_export | 网表、SDC、DEF、时序、route/legality 报告、可选 GDS | 10 |
| 最终检查 | PG connectivity 与 PG DRC，在独立设计副本执行 | 13 |

计划合计 173 分钟，复制、校验和初始化另计。预算为进度提示，超过预算打印 `STAGE_BUDGET_EXCEEDED_CONTINUING`，不会按预算终止尚未保存的原生阶段。三小时是目标，实际耗时必须据服务器日志记录。

新 PG 使用 M7/TM2 ring，M2/M6/M7 84 um 网格、TM2 168 um 网格。M1～M5 在宏周围避让，M1 rails 接标准单元，宏窄 M4 电源 pin 通过 M5 长 pin 策略请求 1×1 接触再接网格。该配置用于减少信号布线资源占用，需要原生检查记录真实连通和违规。

原始约 150 MHz 时钟预算保持。为按交付目标控制计算量，本流程省略完整 `place_opt`、`clock_opt final_opto` 和独立 `route_opt`。报告明确披露这些设置。时钟树构建、时钟布线和信号布线仍实际执行。

## 验收与限制

PG 浮空、PG DRC、signal DRC、setup/hold 违规均保留并报告，不以零违规作为流程继续条件。阶段命令失败、来源不匹配、宏/IO 意外变化、检查点或必要导出文件缺失仍会停止并保留最近完成的检查点。

最终需要 native 阶段完成标记、可用设计库、非空 DEF/网表/SDC/报告，以及普通 NETS 中实际路由记录。结果标记为 `NEW_707CD7F_BASIC_PR_EXECUTED_VIOLATIONS_RETAINED`。它表示基础 PR 动作已执行，详细检查结果见 JSON 与原生报告。可选 GDS 为未核验完整标准单元和 SRAM stream merge 的导出，不作为制造签核成果。

## 运行

服务器入口 `/tmp/tpusoc_basic_pr_20261111_707cd7f_v1.sh`，新输出 `/tmp/tpusoc_basic_pr_707cd7f_*`。

本机 PowerShell 使用 `Get-Content -Raw ... | Set-Clipboard`，服务器 pluma 打开同名脚本并粘贴保存，随后 `sed -i 's/\r$//'` 与 `bash` 执行。前台持续显示各阶段及每分钟运行状态。

如果后续原生阶段失败，在同一工作目录运行 `python3 -u tools/FastEngineeringPr.py "$PWD"` 即可接续。先结束原运行，目录锁会阻止同目录并发启动。已完成阶段不重复，失败尝试另存 retry 目录。
