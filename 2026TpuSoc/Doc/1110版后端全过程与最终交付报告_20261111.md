## ICC2 初始布局与规整 IO

初始布局使用约45%利用率、25 µm core offset；die外框约2599.8×2598.56 µm，外框面积约6.756 mm²。该值包含布局空白和边界，与DC映射面积不同。

971个信号IO按11个接口组分配，整条总线按位序连续排列；时钟/控制及debug/inspect按分组放边，其余接口按边容量分配，保留20 µm拐角避让与组间间隔。左右边使用M3，上下边使用M4，设显式位置约束。坐标、层和位序检查通过；原生pin placement检查Missing、Short、Technology Spacing均为0。初始布局原生184秒完成。

宏数量、未绑定单元以及原始宏物理几何均核对。所有宏PG图形捕获总数14592，均为M4；窄pin宽约0.11至0.28 µm，不能将其全部视作同一宽度。VDDCE/VDDPE逻辑绑定VDD，VSSE绑定VSS；逻辑绑定本身不代表物理供电接通。

## PG 实现与定位过程

首次PG流程在legalize_placement后报告 `MACRO_REF_BBOX changed`。独立诊断表明：固定宏后，加入keepout导致120个cell bbox改变；宏ref、origin、orientation以及三种PG pin绝对坐标未变。修正核验方法为检查真实物理身份，而不拿包含keepout的cell bbox判断宏是否移动。后续采用已保存合法化检查点，避免重复合法化。

第二个问题是 `create_pg_macro_conn_pattern -via_rule` 使用了不适用于该命令的layer-pair结构，触发PGR-002。读取安装版手册后，改用：

```tcl
set_pg_via_master_rule PIN707_1X1 -via_array_dimension {1 1}
create_pg_macro_conn_pattern MACRO707_M5 -pin_conn_type long_pin \
  -direction horizontal -layers M5 -pin_layers {M4} -width 0.28 \
  -spacing interleaving -pitch 42 \
  -via_rule {{intersection: adjacent} {via_master: PIN707_1X1}}
```

宏连接编译成功，提交736 wires和2096 vias并保存pg_complete。但该候选实际PG连接不合格，PG DRC为72606：M2 shorts 15508、V1 overlaps 20884、M1 spacing 13350、V1 spacing 20914、M2 spacing 1174、M4 spacing 776。VDD浮空宏113、标准单元6，VSS浮空宏60、标准单元63。编译成功与检查通过必须分别记录。

之后对外部v6/v7候选在独立副本重做原生检查和有限补via试验。v6实际基线DRC200206，补via后200218，且出现浮空via，因此拒绝采用。v7试验虽DRC1725，但两网各242901个标准单元浮空，供电连通明显恶化，也拒绝采用。不同检查条件/候选的数字不能混用，未以DRC减少替代连通核验。

最终用户明确要求允许PG/DRC/时序违规、优先跑通流程。基础PR从新版初始布局重新生成较稀疏的PG：M2/M6/M7 pitch84 µm、TM2 pitch168 µm，M7/TM2环、M1 rails、M5宏连接；低层在宏周围避让，保留原分组IO。最终仍存在宏供电浮空，不能认定该配置已解决宏连接问题。M4的776项间距问题仍未定位到可证明的根因，不能归因于工艺库自带错误。

## 存储和长 CTS 问题

服务器共享/storage1曾容量和inode同时用满，续跑在写首次JSON时失败，尚未启动EDA。处理为把新输出和设计副本放到本地/tmp，保留NFS上的原输入只读，并校验复制内容。/tmp当时约1.2 TB可用。共享盘后来恢复，最终备份时显示111 GB可用。

完整CTS及其final_opto多轮global route优化耗时过长，曾运行六小时以上。用户选择重新执行允许违规的基础流程。旧新版CTS按PID、工作目录身份核对后发送终止信号，避免与新流程抢占CPU；不使用批量killall。新流程拆分build_clock与route_clock，省略final_opto和独立route_opt；预算超限只提示，不杀尚未保存的原生阶段。

第一次拆分build_clock原生命令约2700秒正常完成，但保存前 `PgCheckSourceIo` 用总端口数严格比较971个信号IO，触发 `Recovered IO port count changed`，因此未保存该CTS结果。修复版逐一核原971个信号IO的存在、坐标与层，只允许额外VDD/VSS命名端口，并打印实际差异；其他新增端口或缺失仍停止。该修复的假设是CTS自动PG连接暴露电源端口，实际新增名称原始日志尚需保留核对。修复后原生全流程已成功完成，证明核验不再阻断此次运行，但不等于全系统功能等价验证。

VNC传输脚本时多次出现SHA不匹配。处理为只规范化UTF-8 BOM、CRLF/CR换行与尾部换行，再比对冻结SHA；匹配后写新的verified文件并运行，未通过降低校验要求绕过。服务器csh与Bash语法不同；后续复杂命令明确用bash -c，find使用/usr/bin/find避免别名影响。自动目录匹配曾未找到进度文件，接续入口改为从显式进入的工作目录读取进度，并核已完成PG/失败CTS记录。
