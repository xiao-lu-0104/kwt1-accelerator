## 2. SRAM 到底怎么改

保留 TPU 内部的 56 个 `RAMSP1024X16`，共 112 KiB；它们是加速器私有工作存储。
平台的 512 KB 共享 SRAM 是另一类存储，由 CPU、加载器和加速器搬运通路访问。
需要补的是共享存储连接和装载流程。

```text
计算机离线提取输入/转换参数
        ↓ 文件准备在计时外
我们实现的加载仿真环境
        ↓ 平台已有访问接口，逐拍握手，装载时间计入任务
平台 512 KB 共享 SRAM（输入、当前层参数、输出、控制信息）
        ↕ DMA / 平台访问桥
TPU 私有 112 KiB SRAM → 计算 → DMA 写回共享 SRAM
        ↑
E203 通过 NICE 下发命令、切换层参数、检查完成与错误
```

现有实现没有 DDR 控制器/PHY，`Sim/DdrModel.h` 是测试用存储模型。
`TpuDma` 本身是通用搬运逻辑，可以继续使用。`TpuAxi` 是 AXI 主接口封装，
是否放在最终数据通路里，取决于平台共享 SRAM 的实际可达端口。

- 若平台提供可访问共享 SRAM 的 AXI 从端口，沿用现有 AXI 主接口，接入平台仲裁。
- 若共享 SRAM 入口是 ICB，首选在 `TpuDma` 的通用 128 位存储接口后接 ICB 访问桥，
  将一次 128 位数据拆成四次 32 位访问，首版仅允许一个未完成请求。
  原 `TpuAxi` 保留供已有回归使用。
- 加载器和 DMA 若共用一个外部入口，需要接入明确的仲裁；CPU、加载器、DMA
  必须访问同一份存储，不能给各通路各放一个互不共享的行为数组。

原平台 O5 的 AXI 示例外设入口是 CPU 访问外设的从机入口，不能直接据此认定
DMA 已能读取共享 SRAM。控制通路继续用 NICE，无须为本计划改成 MMIO 控制。

按照用户转述的群答复，参数加载环境由参赛队实现，不等待额外示例工程。
指南 L41–44 的原表述与该答复不同，提交材料应记录答复来源和采用的加载协议。
加载器只搬运预先转换的输入和权重，必做数值计算全部由 RTL 完成。

### 容量核算

以下采用当前工程 signed16 格式，不能套用旧 int4 工程的容量。

|---|---:|---:|
| 编码器输入或输出 `99×64×2` | 12672 | 12.375 KiB |
| 一层全部编码器参数 | 99584 | 97.25 KiB |
| 独立 FF1 权重及偏置 `(64×256+256)×2` | 33280 | 32.5 KiB |

## 3. 分步实施及验收

### P1：补独立 FF1，保持 112 KiB 私有 SRAM

复用 `TpuMatmul` 已有 `SingleRowEnable`、输入/输出偏移和 FF1 数值路径。
新增独立 FF1 调度：装载一次输入与 FF1 权重/偏置，逐行计算 256 个输出，
每行写回共享存储后复用行缓冲，执行 99 行。
该任务输出是加偏置后的线性结果；现有融合 FFN 中的 GELU/FF2 不参与此任务。

预计改动位置：

- `Rtl/TpuTop.sv`：独立任务状态机、行号、合法性检查、区域占用与最终完成条件。
- `Rtl/TpuDma.sv`：支持内部行缓冲偏移及 256 元素的行传输。
  当前 DMA 从 `SlotBase` 起传输，不能仅改外部地址便读到偏移 7168 的现有行缓冲。
- `Rtl/TpuNice.sv`、`Sw/Tpu.h` 及独立 FF1 驱动：定义输出基址和任务参数的指令编码；
  保持现有 LOAD/EXEC/STORE/STATUS 调用兼容。
- `Model/`、`Sim/`：生成独立 FF1 输入/基准和对应回归入口。

写回一行须等成功的总线写响应；最后一行写响应成功后才发布任务完成。
输入、权重和行缓冲的占用须覆盖整个任务，写回反压期间不得覆盖上一行。
发生 DMA 错误时报告失败，复位须能清除未完成任务状态。

验收：默认紧凑配置下，12 套指定参数各完成 25344 值逐位比较；输入取对应层的
前馈入口（第一处 LayerNorm 之后）。覆盖正常、零值、边界输入、连续换参、
总线等待/错误、中途复位；检查第 0/98 行、输出长度及缓冲边界哨兵。
该功能还须由真实 E203 驱动完成 SoC 回归，不能只交 C++ 直接发命令的结果。
旧 legacy 及 654.39 task/s payload 估算继续作为历史参考。

### P2：接共享 SRAM，完成分层装载

基于 P0 确定的入口实现访问桥和加载器。加载器在运行前读取文件，运行时逐拍
发事务，将输入/当前层参数写入共享 SRAM，再发布层号、长度和 READY 状态。
E203 确认当前层数据有效，发起 DMA 与计算；层参数搬入 TPU 后才能允许重用
共享参数槽。首版按层串行执行，层间激活继续留在 TPU 私有 SRAM。

预计修改 `Sw/SocMain.c`、`Model/MakeSocVectors.py`、平台连接及 `Sim/`：
把现有各层全量常驻地址表改为“当前层缓冲基址 + 参数偏移”，移除对
`0xA0000000` 大容量存储和 `0xA0FF0000` 虚拟控制区的运行依赖。
控制信息放入经核实的 SRAM mailbox，或使用平台已有控制机制。

验收：限制可访问容量，越界失败；逐层更新确实覆盖同一参数缓冲；检查 CPU 与
DMA 的存储可见性、fence、仲裁、请求/响应反压、字节掩码和错误传播。
在真实 E203 与平台连接下跑独立 FF1、单层编码器，并保留十二层换参测试。
先用兼容模型调通的结果须注明模型范围，最终还要在竞赛平台工程里验证。

### P3：完成可引用的功能与周期记录

初赛功能矩阵包含点积/数值处理、独立 FF1、注意力、单层编码器及 E203 联调。
RTL 与本设计定点模型逐位比较；另报告相对浮点参考的误差，二者分开。
补一组有标签验证划分语音的数值模型复核，记录清单、分类头及浮点/定点对照；
现有两个合成/噪声输入的约 0.242% 误差不能写作分类准确率。
不把旧工程的 96.67% 准确率移用到当前数值格式。

计时由第一笔输入/参数装载事务开始，至最后一笔输出写回的成功响应结束。
包含加载器传输、层间等待、CPU 调度/轮询、DMA、仲裁和计算。
文件读取、一次性格式转换和软件分类头位于计时外。
每个计时任务开始前清空任务数据/参数缓存，程序代码可提前准备；禁止在已预装
全部参数后才开始计时。记录总周期、150 MHz 换算、传输字节数及分阶段事件。

交付：独立 FF1 和单层各自的结果/日志/周期，十二层结果单列。
初赛不以决赛统一抽取的 12 个性能任务已完成为前提。

### P4：同一版本重新综合并补功耗估算

FF1 调度、访问桥或集成顶层改变后，重新跑受影响的综合和 150 MHz STA。
旧 hold 修复候选仅对原 checkpoint 有效，不能直接沿用其 WNS。
保存最终 RTL 清单、库及 SRAM 哈希、参数/宏定义、网表、SDC、报告和工具版本。
检查 SRAM 数量、未映射单元、未约束路径和最终 setup/hold；根据实际平台接口
重核原输入输出预算，保留可解释的时序约束。

对最终候选做综合前后功能检查：工具可用时优先形式等价，否则运行对应网表仿真
并说明覆盖范围。18 个新增 buffer 的单元清单不能替代功能一致性验证。

面积分别报告：新增 TPU + 访问桥/接口 + 私有 SRAM 的预算统计；复用的 E203、
共享 SRAM 和固定平台单列。SRAM 单位依据指定面积数据确认，不先将原始库单位
直接称为 mm²。

任务 3 的 L144–145 已包含功耗估算，初赛综合报告应补一份有依据的估算。
对装载到写回的代表任务导出 SAIF/VCD，执行活动映射/覆盖检查和综合功耗估算；
说明库、工艺角、时钟、负载和互连假设。若给出系统平均功耗/能耗，须包含
E203、互连、共享及私有 SRAM；未标注部分不能按零活动处理，缺失 SRAM 模型
不能按零功耗处理。宏功耗补算方法和覆盖限制必须写明。
不要求初赛先完成决赛整套能耗排名实验。

| 报告与干净目录复现 | 约半天 | 最终结果齐备 |

这是工作量估算；接口差异、时序修复和服务器排队会影响日历时间。
