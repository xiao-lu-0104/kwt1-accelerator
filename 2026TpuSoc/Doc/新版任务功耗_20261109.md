# 新版系统任务功耗分析报告（2026-11-09）

本轮已完成FF1 normal和单层Encoder两种任务的SAIF活动采集、严格任务校验和DC功耗报告生成。结果为当前TT条件下的布局前任务功耗估计。内部动态、网络翻转动态和泄漏分项，以及完整内部活动覆盖率仍待从服务器原始报告补齐；不宣称物理签核完成。

## 1. 测量对象与统计范围

设计采用前端提交`c03eb048481b7d271dba54e518092c2eb9aa528f`，对应本轮系统综合目录`~/soc/tpusoc_new_system_dc_20261109_SiVvja`的`mapped/candidate.ddc`，顶层`e203_cpu_top`。分析包含E203 CPU、内部ICB、新版NICE/TPU/DMA/ICB加速器、56个私有SRAM宏和64个共享TCM宏，不包含外部固定外设、封装和板级电源损耗。

| 统计范围 | 包含内容 | 容量说明 |
|---|---|---|
| 系统总功耗 | 上述完整系统综合边界 | 私有112KiB、共享512KiB |
| 加速器小计 | 加速器逻辑及接口＋56个RAMSP1024X16宏 | 私有112KiB |
| 共享TCM | 32个ITCM宏＋32个DTCM宏，均RAMSP4096X16 | ITCM/DTCM各256KiB |

加速器功耗已经包含在系统总功耗中，不能将两者相加。不同任务引起不同电路活动，因此同一系统有不同的任务平均功耗；两个任务也不能相加作为系统总功耗。这些值不代表待机功耗、峰值功耗或芯片所有工作负载的固定功耗。

工艺模型使用本轮已校验的RVT标准单元DB、私有RAMSP1024X16 DB和共享RAMSP4096X16 DB，均为对应TT/1.1V/25℃工程模型。标准库文件名为`scc40nll_vhsc40_rvt_tt_v1p1_25c_ccs.db`；两宏DB文件名分别为`RAMSP1024X16_tt_1p10v_1p10v_25c.db`和`RAMSP4096X16_tt_1p10v_1p10v_25c.db`。实际完整路径与SHA由Inputs.json/RecoveryInputs.json记录。

## 2. 测试任务、固件与正确性检查

测试包含独立FF1 normal和单层Encoder，使用各自输入、参数、小数位配置和黄金输出。单层Encoder是一次`TpuRunLayer`，不是12层网络推理。其驱动执行Q/K/V线性变换、注意力相关计算、输出投影、Norm1、FFN相关计算和Norm2，测试固件最后将结果写回共享存储器。

软件采用1109提交的新驱动。FF1处理99行，按32、32、32、3四块执行与存储；原测试的99次分块计数已适配为4，同时修正FF1新接口中ParameterFraction与OutputAddress的顺序。关键实际代码如下：

```c
// SharedMain.c: Kind=1为FF1；Kind=0为Encoder。
TpuRunFf1(TPU_INPUT, TPU_PARAMETERS, Mail[6], TPU_OUTPUT);

// Encoder.c: 新版FF1分块；完整函数还包括输入/参数LOAD。
for (uint32_t FirstRow = 0; FirstRow < 99; FirstRow += 32) {
    uint32_t Rows = FirstRow == 96 ? 3 : 32;
    TpuFf1Block(FirstRow, Rows, ParameterFraction);
    if (TpuWait(1)) return -1;
    TpuStoreFf1(OutputAddress + FirstRow * 512, Rows);
    if (TpuWait(2)) return -1;
}
```

新固件经实际RISC-V GCC编译，生成Shared.elf、Shared.bin、反汇编、链接映射和完整256KiB Firmware.hex；启动包含31条正常指令清零CPU GPR。编译时的FirmwareEvidence.json保留当时PENDING状态，运行成功以服务器Activity.json和恢复摘要为准，不回改编译证据。

两任务都要求逐值四态黄金比较、DMA读写字节数一致、真实TCM装载及回读通过、ICB镜像无分歧、有效数据/SRAM控制守卫通过，才进入功耗计算。恢复还将原SAIF及日志复制到新验证目录，重新执行同一严格校验，要求重新生成的Activity.json与原记录逐字段一致。以下是代码中必须精确匹配的校验口径，不是额外增加的测试任务：

| 任务 | 黄金输出值数 | DMA读字节 | DMA写字节 | 装载字节 |
|---|---:|---:|---:|---:|
| FF1 normal | 25344 | 45952 | 50688 | 45960 |
| 单层Encoder | 6336 | 112256 | 12672 | 112264 |

必须同时满足的检查还包括：ITCM写入及回读各32768次、DTCM写入及回读各65536次；初始化已释放；new_control_QX=0；ICB divergence_observed=0；活动窗口恰启动/停止一次。完整检查代码见附录中的Tasks.py/validate，不能用“仿真退出0”替代上述条件。

## 3. 如何采集SAIF

采用VCS四态混合仿真：原平台CPU RTL＋本轮冻结的加速器门级网表＋真实私有/共享SRAM功能模型。没有SDF回标，因而不是整个系统的布局后门级仿真。初始仿真编译命令由冻结Run.py构造，关键选项如下，完整文件表和top以实际Task.f及Run.py为准：

```bash
vcs -full64 -sverilog -timescale=1ns/1ps -assert svaext \
  +define+FPGA+FPGA_SOURCE +notimingcheck +delay_mode_zero \
  +vcs+saif_libcell -f Task.f ... -o simv
```

其中`...`仅表示省略的监视器文件及top列表，该节选不能直接独立执行。FF1/Encoder分别运行新固件、各自向量，`KIND=1/0`，均为`LAYERS=1`；共同参数为`INIT_ALL=1`、`INIT_PATTERN=2`、`TASK_SAIF=任务文件`。

初始化条件必须保留：CPU GPR通过启动指令清零；TCM在复位期间经真实封装端口装载并回读；加速器寄存器沿用pattern2一个复位时钟初始化，之后释放。任务开始前初始化驱动均已释放，任务期间不强制DUT信号。该实验不证明未初始化芯片的任意上电状态。

活动范围为完整`SharedTest.Cpu`。原观察模板由冻结Tasks.py生成系统版本，关键语句为：

```systemverilog
$set_toggle_region(SharedTest.Cpu);

// StartWindow中，初始化完成且释放后才开始。
if (!TcmInitializer.Done || !TcmInitializer.Released)
    $fatal(1,"SYSTEM_SAIF_STARTED_DURING_INIT");
StartTime = $realtime;
$toggle_start();

// 最后输出响应被接收后，在随后下降沿结束完整计数周期。
@(negedge SharedTest.Clock);
EndTime = $realtime;
WindowCycles = SharedTest.LastWriteCycle-SharedTest.StartCycle+1;
WindowError = EndTime-StartTime-WindowCycles*6.667;
if (WindowCycles==0 || WindowError>0.002 || WindowError< -0.002)
    $fatal(1,"Task SAIF window does not match complete counted cycles");
$toggle_stop();
$toggle_report(ActivityFile,1.0e-12,"SharedTest.Cpu");
```

以上为同一观察器不同位置的节选；完整可核对版本见附录Derived/SystemActivity.sv及生成它的Initial/tools/Tasks.py。窗口从测试平台定义的首个输入请求至最后输出响应对应的完整计数周期，排除初始化过程，不等于整个仿真总耗时。SAIF时间单位使用ps；仿真时钟实际6.667ns，DC预算6.666667ns，二者的精度区别如实保留。校验SAIF头部时长与周期数×6.667ns相符，能量使用SAIF实际时长。

同时确认SAIF中存在CPU和共享SRAM层次、有非零翻转活动；统计TX/TZ非零记录和最大单记录TX时长占比。未将X活动清零或设置全局未知豁免。

## 4. DC功耗计算与关键Tcl

原始仿真目录为`~/soc/tpusoc_current_power_20261109_Msc1ap`，恢复功耗目录为`~/soc/tpusoc_power_resume_20261109_FnT5fI`，后缀大小写及易混字符以服务器原输出为准。恢复只读取已保存的本轮SAIF和本轮系统DDC，未重新综合或仿真。原始数据、工具和失败日志保持不变，新报告独立保存。

先启用名称映射，再读取DDC、链接并校验核心周期及三路已有时钟，之后读取新SAIF。保留原时序预算，不重复创建DDC内已有的generated clock。实际恢复Power.tcl的主要代码如下，依赖环境变量由Power.py设置：

```tcl
set target_library [list $::env(TPU_STDCELL_DB)]
set link_library [concat [list *] $target_library \
    [list $::env(TPU_SRAM_DB) $::env(TPU_SYSTEM_DB)]]
saif_map -start
read_ddc $::env(NEW_POWER_DDC)
current_design e203_cpu_top
link
reset_switching_activity -all
if {[read_saif -input $::env(NEW_POWER_SAIF) \
    -instance_name SharedTest/Cpu -auto_map_names] eq "0"} {
    error "Current full-system task SAIF annotation failed"
}
redirect saif_global.rpt {report_saif}
redirect power.rpt {report_power}
redirect saif_hierarchy.rpt {report_saif -hierarchy}
redirect saif_missing.rpt {report_saif -hierarchy -missing}
redirect power_hierarchy.rpt {report_power -hierarchy}
redirect units.rpt {report_units}
```

除全局报告外，按互斥叶集合计算七类功耗：加速器逻辑及接口、加速器私有SRAM、CPU及内部ICB、共享ITCM宏、共享DTCM宏、共享TCM适配逻辑、其他系统逻辑。分类复用面积报告的AreaClass，排除常量伪叶，检查宏分组数量56/32/32：

```tcl
set Key [AreaClass [get_object_name $C] $Ref]
set Groups($Key) [add_to_collection $Groups($Key) $C]
# 对各组分别执行，Count为该组实际叶数量。
redirect "${Key}_power.rpt" {
    report_power -cell -only $Groups($Key) -nworst $Count -nosplit
}
```

报告脚本前后比较全部叶名称/引用和时序预算，保证功耗阶段没有优化或修改网表。解析器只接受原生报告明确标出的W/mW/uW/nW/pW单位，检查内部动态＋翻转动态与总动态的和一致。分组总和与全局总量的差额保留在`group_sum_minus_system_total_w`供审查，不强行修正使其闭合。

## 5. 实际结果及含义

恢复最终返回`CURRENT_SYSTEM_TASK_POWER_REPORTS_COMPLETE_REVIEW_PENDING`，入口exit0，`ORIGINAL_INPUTS_UNCHANGED: True`。FF1和Encoder原生DC分别1088秒、1087秒exit0。每项约18分钟是工具分析耗时，不是芯片执行任务的时间。

| 任务 | 系统总功耗 mW | 加速器小计 mW | 系统任务能量 µJ |
|---|---:|---:|---:|
| FF1 normal | 52.6655286 | 40.759028 | 57.72781662735905 |
| 单层Encoder | 52.2207637 | 41.387047 | 186.2306432513572 |

总功耗与任务能量的定义为：

\[
P_{dynamic}=P_{internal}+P_{switching},\qquad
P_{total}=P_{dynamic}+P_{leakage},\qquad
E_{task}=P_{total}\times T_{SAIF}.
\]

加速器小计为加速器逻辑及接口和私有SRAM两组同一物理量的和。能量来自任务窗口平均功耗与实际SAIF时长，不包含本次被排除的初始化阶段，也不是板卡电源实测。

两项任务的平均系统功耗接近，但Encoder任务能量更大，说明仅比较平均功耗不足以描述一次任务的能耗；执行时间也参与决定能量。任务周期和时长的原始数值保存在Activity.json，当前截图未完整回传，不把从已打印功耗/能量反推的值当成原始测量值填入报告。

## 6. 活动覆盖与结论边界

截图中两任务全局report_saif表均为：nets总数693、ports971、pins12，全部标为user，propagated/default为0。这只证明该表所展示对象的标注情况，不能说所有内部门引脚均100%覆盖。脚本还保存层次、missing及CPU核心/加速器/共享TCM区域报告，完整覆盖审查仍待进行。

FF1的TX非零记录数为10668，Encoder为14387。这是SAIF记录数，不是未知信号占比，也不直接等于错误数。须结合有效数据守卫、未知持续时间和内部标注覆盖共同解释；没有用全局X豁免将其隐藏。

可以确认的是：两种新版任务通过本轮严格校验，新活动已用于当前系统候选的原生功耗报告，报告生成成功且原输入不变。尚不能据此宣称整个系统RTL到门级等价、所有内部活动充分标注、真实上电状态覆盖或布局后功耗签核完成。混合仿真中的CPU RTL到门级活动映射、SRAM模型及无物理寄生/实际时钟树都是当前估计的限制。
