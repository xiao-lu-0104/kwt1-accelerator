# 研究生组初赛收尾计划

日期：2026-11-04；执行状态更新于 11 月 5 日。
独立 FF1、共享 SRAM 逐拍分层加载及 CPU/TCM 接入已实现；
正式平台源码和厂商私有 SRAM 功能模型的十七项回归全部通过。
当前进入新配置综合/时序阶段；网表功能、功耗和完整外设 SoC 顶层仍待验证，见
[共享存储记录](../Server/Results/20261105_Shared.md)。
起点：已核对的 main `58e1a3666060e27e2fd7d04129c9dabaee6baf34`。
目标：在同一套可复现配置下完成任务 1—3、注意力、单层编码器及初赛交付材料。

## 1. 确定保留的基础和实际改动

保留现有数值规则、点积/非线性计算数据通路、NICE 控制接口、DMA 和
56 个 RAMSP1024X16（112 KiB）私有 SRAM。独立 FF1 采用用户选定的逐行计算、逐行写回，
不以扩容或 legacy 配置作为正式验收方案。

当前 C++ 测试环境中的 16 MiB DDR 存储及一次性全模型预装不作为正式加载路径。
现有设计没有 DDR 控制器，AXI 接口本身也不等于 DDR；需要替换的是平台连接、
加载环境、内存布局和计时方式。FPGA/DDR 测试入口保留为历史功能对照。

目标数据链路：

```text
计算机文件（仿真前读取与格式转换，计时外）
  → 加载器按平台 ICB 握手逐字写入（计时内）
  → 平台已有共享存储：当前输入、当前层权重、结果
  ↔ TPU DMA 与平台存储之间的 128-bit/32-bit 适配器
  ↔ TPU 私有 SRAM：56 个现有宏
  → 加速器计算 → DMA 写回平台共享存储
```

ITCM 用于启动和驱动程序；大批模型系数放在数据存储区，按层覆盖复用。
初版顺序装载和执行，采用一套参数缓冲，不做双缓冲预取或新增时钟域。
十二层模型文件可以全部保存在测试平台的文件缓存中，但不能全部常驻被测 SoC，
不能通过层间零周期 memcpy 绕过真实总线传输。

## 2. 按依赖顺序实施

### P0：核对服务器平台，固定集成接口

- 只读核对服务器原工程 `~/soc/e203_hbirdv2-master` 的配置、内存图、NICE 插槽、
  ITCM/DTCM 控制器及外部 ICB 访问口，记录文件哈希和原 CPU 回归入口。
- 本地历史平台快照为 ITCM/DTCM 各 256 KiB、32-bit ICB；它只提供接口线索，
  不复用旧 KWT 加速器、旧 MMIO 补丁或旧 int8 权重布局。
- 采用平台已有 NICE 插槽接当前 TpuNice，保留处理器译码和执行数据通路。
  正式存储侧使用 NICE 的 32-bit memory ICB 通路，经原 LSU/TCM 控制器访问 DTCM；
  加载器通过平台已有 external-to-DTCM ICB 口写入，不为共享内存增加旁路端口。
- NICE 控制命令保持 LOAD/EXEC/STORE/STATUS；DMA 仍由 E203 发命令后异步执行。
  `nice_mem_holdup` 不置位来阻塞整个任务，CPU 和 DMA 竞争内存产生的等待正常计时。
- 原工程若与上述容量或接口不符，P0 输出具体差异，先修订接口计划，
  不自行增加一块 512 KiB 存储、不改容量凑数、不宣称正式平台联调完成。

P0 完成标志：平台接口/容量/基址及库文件清单确认，原 CPU 冒烟回归通过。

### P1：在 112 KiB 配置补齐独立 FF1

- 复用 TpuMatmul 已有 SingleRowEnable 和源/目标偏移输入，不改乘加、偏置、舍入与饱和规则。
- 在 `TpuNice`/`TpuTop` 中新增 EXEC shape 10，表示 FF1 的单行计算。
  沿用 funct7=EXEC；rs1 使用原 metadata 编码，rs2 低 7 位传 row=0..98，其他位为零。
  原指令编码行为保持兼容，其他旧 EXEC 的 rs2 仍为零。
- 首版固定独立任务槽位：slot 0 保存全部 99×64 输入，slot 6 保存 FF1 权重及偏置，
  slot 1 保存当前行 256 个输出；三个活跃范围不冲突。
  单行源偏移为 row×64，目标偏移为零。
- 新增 DMA 数据规格 9，表示 256 个 signed16 元素，即一行 512 字节。
  CPU 在每行计算完成后执行 STORE，外部地址为 output_base+row×512；
  收到该行最终写响应后才启动下一行。全部 99 行写回完成才报告任务完成。
- 驱动提供 `TpuRunFf1(input_addr, ff1_param_addr, output_addr, fraction)`：
  输入和参数各 LOAD 一次，随后执行 99 次单行 EXEC/STORE。
- row>=99、非零保留位、非法槽位或不合法尺度置错误，不产生非法 SRAM 写。
  执行中复位清除任务有效状态，重新装载后再运行。

P1 完成标志：当前 56 宏配置中，用十二层各自参数完整写出 25344 个有效元素，
逐元素匹配定点参考；正常、零值、极值、连续换参、反压和复位测试通过。
旧融合编码器回归保持通过。该阶段得到实际周期，删除将 payload 估算当作实测的表述。

### P2：接共享存储并实现分层加载

- 新增存储适配器，将 DMA 的每个 128-bit beat 拆成 4 个按地址递增的 32-bit ICB 请求，
  小端打包、一个 outstanding；读齐四字后交付一拍，写满四个响应后才交付该拍完成。
- 保留 valid/ready 反压和固定长度包约定。读错误按对应拍上报，写错误累计到最终响应，
  不提前丢弃尾拍造成现有 DMA 挂起；越界请求不得访问真实内存。
- 在 P0 核实各 256 KiB 后，采用以下数据内存布局，所有 C/RTL/TB 地址由一个布局描述生成：

| 范围 | 容量 | 用途 |
|---|---:|---|
| 0x80000000–0x8003ffff | 256 KiB | 平台 ITCM：程序、启动及少量配置 |
| 0x90000000–0x90000fff | 4 KiB | 任务/层就绪、释放、完成、错误和尺度元数据 |
| 0x90001000–0x90004fff | 16 KiB | 输入，最多 12672 个有效字节 |
| 0x90005000–0x90014fff | 64 KiB | 输出，覆盖 FF1 的 50688 字节或编码器输出 |
| 0x90015000–0x90034fff | 128 KiB | 当前层参数区，覆盖当前单层 99584 字节 |
| 0x90035000–0x9003ffff | 44 KiB | data/bss、栈及软件工作区 |

- 测试加载器读文件后只通过真实平台 ICB 事务写数据。每次只写当前层，
  等待全部响应后发布 layer-ready；CPU 完成本层、确认参数不再使用后发布 layer-released，
  加载器才能覆盖参数区。结果由 CPU 配置 DMA 写回，TB 只核对。
- 原本静态指向十二层全部参数镜像的地址表改为当前参数区的固定偏移，
  每层更新 fractions/就绪标记；编码器中间激活仍保留 TPU 内部，不借加载器代算。
- 时钟沿、内存延迟、CPU/DMA/加载器争用全部来自平台控制器和实际握手。
  初赛配置不加入 DDR 刷新/600 MB/s 限速假设，不虚构串口等未使用接口的加载速度。

P2 完成标志：容量/越界断言通过；共享存储中不常驻完整模型；
独立 FF1、注意力、单层与十二层保留回归均由真实 E203 执行命令完成。
加载器不直写 TPU 私有 SRAM，不提供算子中间答案。

### P3：固定完整任务计时，重新运行验证和综合

- 程序加载和 CPU 启动放在任务准备阶段，输入/参数文件读取及一次性格式转换在计时外。
  各任务清空有效状态后，从加载器首次发出输入或参数写请求的周期开始计时；
  到最后一笔结果写回的成功响应结束。所有后续层装载、等待、调度、计算和写回均计入。
- 输出加载字节/周期、DMA 读写字节、总周期、计算周期、等待周期以及错误状态。
  FF1、单层、十二层三个任务单独统计，不用计算核周期冒充完整任务吞吐。
- 对新增适配器验证小端、连续传输、响应延迟、反压、错误、复位和地址边界；
  对分层装载验证延迟就绪、禁止提前覆盖、连续任务及最后写响应之前不能 DONE。
- 新 RTL/平台接线产生新冻结配置，必须重新执行厂商宏测试及 150 MHz SMIC40 综合/STA。
  核对 56 个内部真实宏、全部叶单元、时钟和约束，不沿用旧 hold_candidate 的 PASS。
- 对新增配置执行 hold 修复并生成独立候选及前后差异；补一次综合网表功能仿真。
  不通过缩小 uncertainty、宽泛 false path 或变更任务配置取得通过。

P3 完成标志：同一冻结配置的功能、数值、任务计时、宏绑定及 setup/hold 均有日志；
综合网表功能检查通过。平台/库功能模型若缺失，先列出缺失输入，不标成通过。

### P4：功耗、面积和初赛材料

- 对 P3 的最终配置生成完整任务窗口的活动信息，映射至同一综合网表做功耗估算，
  报告活动覆盖率。CPU、互连、TPU 以及 SRAM 的动态/静态功耗都要有依据；
  无标注电路或无模型 SRAM 不按零活动/零功耗处理。
- 面积按赛题口径报告：新增接口、DMA、TPU 逻辑和内部 SRAM 合计核验 2.25 mm²，
  E203、平台共享 SRAM 和固定外设单列。确认宏/标准单元单位，不把库原始数值直接当 mm²。
- 整理一个正式版本：RTL、驱动、模型/转换、参考向量、测试入口、最终网表、SDC、
  功能/误差、时序/面积/功耗、周期/吞吐、工具版本、源码/参数/产物校验值。
- 用官方预训练权重生成 FF1 及编码器输入；补一组有标签真实语音的小样本数值检查。
  如给出分类结果，注明样本范围，不把两个合成/噪声输入的误差当作准确率。
- 统一 SMIC40 实测、FPGA 历史对照和未验证的 TSMC22 目标叙述；初赛不新增布局布线、
  板级 DDR PHY、模型重训、600 条完整决赛评测或新的架构优化任务。
- 报告以实测数据为准。确认指定工艺若与现用 SMIC40 不一致，单列待组委会确认事项，
  不把不同工艺的面积/时序数字拼接为一套。

P4 完成标志：在干净环境按说明复现主要测试与报告，所有提交文件来自同一冻结配置。
代码修改通过独立 PR 交付，不自动合并。

## 3. 分工、顺序与完成标准

| 阶段 | 主要类型 | 由助手负责 | 用户需要配合 |
|---|---|---|---|
| P0 | 平台核对 | 准备只读核查、比较源码/接口并固定配置 | 提供服务器平台路径或执行核查命令 |
| P1 | RTL、驱动、测试 | 逐行 FF1 路径及回归 | 核对方案，运行必要的服务器测试 |
| P2 | 适配、加载器、固件 | ICB 适配、层加载、内存布局和真实 E203 联调 | 执行服务器命令，保留日志 |
| P3 | 仿真、综合、计时 | 自动化脚本、失败定位、结果关联 | 执行服务器工具，回传结果 |
| P4 | 报告与交付 | 根据实际数据生成技术报告、表格和复现说明 | 确认队伍信息、组委会口径、最终审阅及上传 |

P0 是平台接线的前置条件；P1 可在现有核级环境先做；P1/P2 完成后进行 P3，
最后用冻结结果完成 P4。报告框架可提前整理，数值在最终测试后填入。
本计划不要求用户从零手写报告，也不会只改报告而跳过缺失的功能/集成。
