## 3. 综合与验证方法

1. 固定新版 RTL 及平台集成输入，记录 SHA，进行集成 lint。仅复用审查通过的工艺和参考库，不直接执行旧冻结流程充当新版运行。
2. 加速器执行主综合并保存 `baseline.ddc/v/sdc`。初次运行在后续 SRAM hold 修复阶段达到2400秒保护上限而退出；主综合基线已成功保存。
3. 在新目录加载该 baseline，核对顶层、56宏、唯一 SRAM 绑定及完整时序预算，再执行增量 hold 修复；不重新运行 RTL 主综合。保存候选后输出面积、setup/hold、约束与检查报告。
4. 审查 baseline→candidate 的叶单元变化；原生 Formality 对这两个门级版本执行增量等价，match/verify均返回1。证明范围为本轮 hold 修复前后门级版本，不扩大为 RTL→网表、SRAM 内部或全系统等价。
5. 集成 E203、内部 ICB 和共享 TCM，冻结加速器，并在系统映射及必要 hold 修复前后核对加速器叶名称/引用签名、宏数和时序预算，输出系统 DDC、网表、SDC、面积分项及 STA 报告。
6. 对固定新版重新生成固件和严格黄金任务，采集新 SAIF，再加载本轮系统 DDC 进行活动标注和功耗报告；未复用1109的旧 SAIF。

关键 Tcl 摘录如下，变量与保护循环以附录完整冻结脚本为准：

```tcl
# 加速器主综合及基线保存
compile_ultra -no_autoungroup -no_boundary_optimization
write -hierarchy -format ddc -output [file join $Out baseline.ddc]

# 独立恢复：加载已保存基线，保持预算，增量修复 hold
read_ddc [file join $Input baseline.ddc]
current_design e203_subsys_nice_core
link
set_fix_hold [get_clocks CoreClock]
compile -incremental_mapping -only_hold_time
write -hierarchy -format ddc -output [file join $Out candidate.ddc]
write_sdc -nosplit [file join $Out candidate.sdc]
report_area -hierarchy
report_timing -delay_type max -max_paths 20 -significant_digits 6
report_timing -delay_type min -max_paths 20 -significant_digits 6

# 每项新版任务的系统功耗分析
saif_map -start
read_ddc $::env(NEW_POWER_DDC)
current_design e203_cpu_top
reset_switching_activity -all
read_saif -input $::env(NEW_POWER_SAIF) -instance_name SharedTest/Cpu -auto_map_names
redirect saif_global.rpt {report_saif}
redirect power.rpt {report_power}
redirect saif_hierarchy.rpt {report_saif -hierarchy}
redirect power_hierarchy.rpt {report_power -hierarchy}
```

加速器独立候选总面积为1,133,402.68238 µm²，含逻辑/接口621,085.315201 µm²和私有 SRAM 512,317.367184 µm²。分项与总值末位可能存在报告舍入差。

私有存储：56×1024×16 bit =112 KiB。共享存储：64×4096×16 bit =512 KiB，ITCM/DTCM各32宏、各256 KiB。系统存储容量合计624 KiB。

加速器 hold 修复新增296个 BUF/DEL 单元，其中 SRAM 范围内276个、范围外20个；没有删除或替换原叶单元引用。修复前总面积1,131,902.44238 µm²，修复后1,133,402.68238 µm²，增加1,500.24 µm²。范围外变化经过结构审查，并用上述本轮门级增量等价核验，未沿用1109证明。

系统检查保留了 `core_csr_clk`、`inspect_core_clk` 转发时钟输出的 maximum-delay 未约束提示，未通过随意增加 false path 隐藏。`nice_rsp_rdat`高位及部分命令尺寸输出常量的 LINT-52 提示也保留。报告完成与目标路径 WNS为正，不等同于全报告零警告。

## 6. 新版任务活动标注功耗

两项任务均采用本轮新版固件与新 SAIF，运行严格黄金结果、DMA/ICB事务、8路DOT、有效数据及初始化释放守卫。仿真采用 CPU RTL 与新版冻结加速器门级网表、真实120个SRAM模型的混合四态环境；零延迟、无SDF，有明确初始化条件，不能称全系统带时序门级仿真。

| 指标 | FF1 | 单层 Encoder |
|---|---:|---:|
| 任务周期数 | 120,050 | 365,457 |
| 活动统计时长 / ms | 0.80037335 | 2.436501819 |
| 系统动态功耗 / mW | 74.6018 | 74.2333 |
| 系统泄漏功耗 / mW | 0.437211 | 0.4372013 |
| **系统总功耗 / mW** | **75.039011** | **74.6705013** |
| 加速器区域总功耗 / mW | 62.309350 | 63.347308 |
| **系统任务能量 / µJ** | **60.0592246148** | **181.9348122431** |
| 活动记录 TX_nonzero | 11,133 | 26,034 |

任务能量按系统总功耗×SAIF实际统计时长计算，不以服务器仿真耗时计算。例如 FF1：75.039011 mW×0.80037335 ms=60.0592246148 µJ。

global覆盖表中 nets693、ports971、pins12 均标为user，propagated/default为0；此结论只适用于该表对象，**不代表全部内部节点100%活动覆盖**。层级覆盖、默认传播及TX/TZ限制保留于原报告。功耗单位按 `report_power` 的明确W/mW等单位解析，不使用 `units.rpt` 的 `Power_unit N/A` 推算。

结果适用于所测任务及初始化/活动条件，未覆盖峰值功耗、全部工作负载、布局布线寄生、时钟树、IR/EM、温度分布或芯片实测。不得将加速器区域功耗与系统总功耗混用来计算系统任务能量。
