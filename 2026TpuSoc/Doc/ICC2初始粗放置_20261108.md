## 实际执行内容

1. 核对原PrSummary、输入SHA、原网表固定SHA、三个原生阶段退出/日志SHA，以及两个工作区的成功/无不匹配报告。
2. 对设计库及两个NDM当前全部普通文件保存SHA清单，拒绝符号链接/特殊文件及超限库。
   这是下一阶段开始时捕获的指纹；旧入口没有建库时指纹，不能把这次指纹写成建库时已验证的SHA。
3. 在新`tpusoc_icc2_coarse_20261108_XXXXXX`目录复制三份库，逐文件核对复制相同；原库不打开、不覆盖。
4. ICC2打开设计副本，将参考库路径改到NDM副本，打开原顶层并重新link，核对原叶数量和零未解析实例。
5. 读取安装版手册确认命令/选项；限制最多4核，运行`create_placement -floorplan -effort low`。
   这是几何初始粗放置，不启用timing-driven或place_opt，不出RC时序收敛结论。
6. 核对所有逻辑叶实例名称/库引用与放置前相同；输出native macro bbox、core_area_bbox、宏重叠报告和新DEF，保存副本。
7. Python独立检查：恰56个宏、各宏面积与已核对物理占地一致、宏不重叠且在矩形core内；DEF中的同一批宏必须有放置状态；原生宏重叠统计也必须明确为0。
8. 重新核对原输入及三份原库未变，才记录阶段完成。

缺命令/属性、放置失败、几何或清单不符都保存诊断并停止，不降低接受条件。
本阶段只检查矩形core及矩形SRAM bbox；不等于宏栅格/方向/间距、通道、电源、引脚可达性或标准单元合法性全部通过。

## 输出与如何理解

| 输出 | 用途 |
|---|---|
| `CoarseInputs.json` | 原输入及三份原库的当前SHA清单、复制来源、阶段边界 |
| `CoarseSummary.json` | 原生运行结果、独立几何检查、原输入是否未变及错误 |
| `MacroGeometry.json` | core矩形和56个宏的实际native bbox |
| `MacroPlacement.svg` | 按native坐标绘制的SRAM分布示意；可在服务器图形界面打开；不包含全部标准单元/布线 |
| `design/accelerator.nlib` | 放置后的设计副本；仅在服务器保存 |
| `design/coarse_floorplan.def` | 此阶段导出的物理位置 |
| `design/report_placement.rpt` | 原生宏重叠统计；其余物理检查仍待后续 |
| `CoarseReports.partial.tar.gz` | 诊断/配置/坐标/DEF/SVG，排除NDM/nlib，不主动下载 |
