# 新版加速器与E203系统 DC 综合阶段报告

报告日期：2026年11月9日。本报告包含新版加速器及E203系统两阶段综合结果。
hold修复前后网表已取得Formality工具比较通过结果，完整黑盒边界审查及系统原生检查报告核对仍待补充。

本轮已取得新版加速器的工艺映射候选及布局前静态时序结果：候选含56个私有SRAM宏，
库叶单元总面积约0.893357mm²；在150MHz目标和既定TT工程约束下，
最差setup、hold裕量均为正。当前结论限于已加载的工艺模型和时序约束，
增量形式比较的边界审查及候选验收仍待完成。

## 1. 对象与分析条件

本轮针对 Git 提交 `c03eb048481b7d271dba54e518092c2eb9aa528f` 的新版加速器开展综合，
计算部分包含32路共享权重MAC、向量SRAM读取流水和DMA STORE流水。
顶层为 `e203_subsys_nice_core`，由该提交中的13份RTL与原系统的
`TpuIcb.sv`、NICE集成封装及真实SRAM适配层组成。
范围包括NICE、TPU、DMA、ICB接口及112KiB私有SRAM，尚不包含E203 CPU和共享TCM。

综合与分析工具为 Synopsys Design Compiler T-2022.03-SP5-5。
采用SMIC40 RVT标准单元与RAMSP1024X16的TT模型，工作条件1.1V、25℃。
本轮约束如下。所有数据IO使用同一主时钟预算，未通过添加false path或multicycle path放宽检查。

| 约束项                   | 设置                                    |
| ------------------------ | --------------------------------------- |
| 时钟名称及端口           | CoreClock / nice_clk                    |
| 目标频率 / 周期          | 150MHz / 6.666667ns                     |
| Setup / hold uncertainty | 0.200ns / 0.100ns                       |
| 时钟transition           | 0.100ns                                 |
| 输入延迟max / min        | 1.000ns / 0.100ns                       |
| 输入transition           | 0.100ns                                 |
| 输出延迟max / min        | 1.000ns / −0.100ns                     |
| 输出负载                 | 0.035pF                                 |
| 时序分析阶段             | 布局前、理想时钟网络、top模式线负载模型 |
| 系统原生时间 / 负载单位  | ns / pF（units.rpt已核对）              |

输入输出延迟用于预留加速器外部逻辑及接口传输的时间预算，clock uncertainty用于计入
时钟相关的不确定性。负的输出min delay是本轮采用的保持时间接口预算，不能直接解释为时序违例。
这些结果不代表布局布线后时序或多角签核。

## 2. 库准备与加载

完成厂商SRAM模型及Liberty输入文件的SHA256核验，在私有运行目录中将TT Liberty转换为DC DB，
并由DC成功加载标准单元与SRAM库。该步骤建立了工艺映射、面积统计及静态时序分析所需的模型。

## 3. 综合与结果核对流程

首先固定本次源码版本与集成文件，记录源码SHA256并核验运行包完整性；
随后加载工艺库，对SystemVerilog源码执行analyze、elaborate和link，
展开加速器层次并检查56个真实SRAM宏的绑定数量。

在施加主时钟及IO预算后，使用
`compile_ultra -no_autoungroup -no_boundary_optimization`
完成工艺映射。该配置保留模块层次并关闭边界优化，便于追踪NICE、计算核心、DMA和SRAM边界。
SRAM宏设置dont_touch，防止将宏替换为通用逻辑。

首次映射后保存baseline的DDC、Verilog网表和SDC，以便保留原始结果。
当报告出现负hold裕量时，设置hold修复目标，执行一次
`compile -incremental_mapping -only_hold_time`，并保存candidate检查点。
对两个检查点重新启动独立DC会话，分别读取DDC、链接工艺库并提取面积、时序和完整叶单元清单。
重新分析过程中未重新施加其他SDC或执行综合优化，原检查点和库文件前后SHA保持不变。

已核对两份保存SDC的时序要求文本一致，比较时排除了set_fix_hold和set_dont_touch这两类
优化控制命令。该比较不代表任意SDC改写的语义证明，仅用于本轮原生输出的约束一致性核对。

以下为实际执行脚本节选，完整代码与依赖见[脚本附录](DC综合脚本附录_20261109.md)。环境变量由服务器入口设置并校验，正文节选不构成可独立执行的脚本。

### 3.1 工艺库配置与源码读取

target_library指定标准单元映射目标，link_library同时包含标准单元和SRAM库，用于解析已有单元引用。TPU_SRAM_MODEL选择显式bank分支，由真实宏适配层实现。

```tcl
set Tools $::env(TPU_SHARED_TOOLS)
set Source $::env(TPU_SHARED_SOURCE)
set Out $::env(TPU_ASIC_OUT)
set Top e203_subsys_nice_core
set target_library [list $::env(TPU_STDCELL_DB)]
set link_library [concat [list *] $target_library [list $::env(TPU_SRAM_DB)]]
file mkdir $Out
cd $Out
set_app_var verilogout_no_tri true
set_host_options -max_cores 4
set_svf [file join $Out guidance.svf]
saif_map -start
set_app_var search_path [concat $search_path [list $Source]]
define_design_lib WORK -path [file join $Out work]
source [file join $Source Sources.tcl]
if {![analyze -format sverilog -define {SYNTHESIS TPU_SRAM_MODEL} -library WORK $Sources]} {
    error "RTL analyze failed"
}
elaborate $Top -library WORK
current_design $Top
if {![link]} {error "Initial link failed"}
```

### 3.2 时钟与接口预算

时钟周期和IO延迟直接影响综合目标与时序检查结果，因此保留完整约束。输入时钟nice_clk不施加数据输入延迟，其余输入均有预算；输出同时设置max/min延迟和负载。

```tcl
# Same explicit engineering budgets as the previous 150 MHz TT study.
# This top is the synchronous NICE engine. Its reset is driven by the platform.
create_clock -name CoreClock -period 6.666667 [get_ports nice_clk]
set_clock_uncertainty -setup 0.200 [all_clocks]
set_clock_uncertainty -hold 0.100 [all_clocks]
set_clock_transition 0.100 [all_clocks]
foreach_in_collection Port [all_inputs] {
    if {[get_object_name $Port] eq "nice_clk"} {continue}
    set_input_delay -clock [get_clocks CoreClock] -max 1.000 $Port
    set_input_delay -clock [get_clocks CoreClock] -min 0.100 $Port
    set_input_transition 0.100 $Port
}
foreach_in_collection Port [all_outputs] {
    set_output_delay -clock [get_clocks CoreClock] -max 1.000 $Port
    set_output_delay -clock [get_clocks CoreClock] -min -0.100 $Port
    set_load 0.035 $Port
}
# No false path or multicycle exception; CPU<->NICE/ICB are budgeted IO.
if {[sizeof_collection [all_clocks]] != 1} {error "Expected one clock"}
```

### 3.3 SRAM保护、工艺映射与初始检查点

检查56个真实宏并设置dont_touch后执行compile_ultra。DDC保存设计数据库，Verilog保存结构网表，SDC保存该阶段约束。

```tcl
set Macros [get_cells -hierarchical -filter {ref_name == RAMSP1024X16}]
if {[sizeof_collection $Macros] != 56} {error "Expected 56 real private SRAM macros"}
set_dont_touch $Macros true
source [file join $Tools Constraints.tcl]

puts "DC_STAGE: compile_start"
if {![compile_ultra -no_autoungroup -no_boundary_optimization]} {error "compile_ultra failed"}
write -hierarchy -format ddc -output [file join $Out baseline.ddc]
write -hierarchy -format verilog -output [file join $Out baseline.v]
write_sdc -nosplit [file join $Out baseline.sdc]
puts "DC_STAGE: baseline_saved"
```

### 3.4 一次增量hold修复与候选保存

仅当初始hold裕量为负时启动一次hold-only增量优化。以下保留实际范围选择与保护代码；InSram、SramAncestor在附录HoldPolicy.tcl中定义。实际新增单元分布和后续比较结果见第6节，不能仅凭dont_touch设置推断全部结构或连接保持不变。

```tcl
if {$BeforeHold < 0} {
    puts "DC_STAGE: sram_hold_start"
    # One bounded attempt restricted to SRAM; preserve all sibling logic and IO.
    set Scope [get_cells -quiet Tpu/Core/Sram]
    if {[sizeof_collection $Scope] != 1} {error "Missing preserved SRAM hierarchy"}
    set Frozen ""
    foreach_in_collection Cell [get_cells -hierarchical] {
        set Name [get_object_name $Cell]
        if {![InSram $Name] && ![SramAncestor $Name]} {
            set Frozen [add_to_collection $Frozen $Cell]
        }
    }
    set_dont_touch $Frozen true
    set_dont_touch [get_cells -hierarchical -filter {ref_name == RAMSP1024X16}] true
    set_fix_hold [get_clocks CoreClock]
    if {![compile -incremental_mapping -only_hold_time]} {error "Hold-only compile failed"}
    set Repaired 1
}
write -hierarchy -format ddc -output [file join $Out candidate.ddc]
write -hierarchy -format verilog -output [file join $Out candidate.v]
write_sdc -nosplit [file join $Out candidate.sdc]
```

## 7. E203系统集成与综合结果

### 7.1 集成范围与实现方法

将本轮加速器candidate.v作为冻结结构网表接入E203平台，以e203_cpu_top为系统综合顶层。
系统范围包含CPU、内部ICB、NICE/TPU/DMA、112KiB私有SRAM及512KiB共享TCM；
外部固定外设不在本轮映射范围。共享TCM由256KiB ITCM和256KiB DTCM构成，
共使用64个RAMSP4096X16宏，连同56个私有宏，系统共120个SRAM宏。

复用已核验历史指纹的CPU/平台源码、TCM适配层及共享SRAM DB，并使用本轮加速器对应的
标准单元及私有SRAM DB，不重复转换库。集成后对加速器叶单元逐项核验，
再冻结加速器及全部SRAM宏，对其余CPU、内部总线和TCM适配逻辑进行综合。
对应实际代码如下，Scope为此前核验的加速器实例集合。

```tcl
    set_dont_touch $Scope true
    foreach Ref {RAMSP1024X16 RAMSP4096X16} {
        set_dont_touch [get_cells -hierarchical -filter "ref_name == $Ref"] true
    }
```

系统根时钟为clk，对应150MHz的CoreClock。inspect_core_clk、core_csr_clk为转发时钟输出，
脚本核验其扇入起点仅为clk后建立一分频组合generated clocks，并保留输出负载。
这两个时钟输出不施加数据output_delay，其余数据IO预算保持；不添加false/multicycle例外。

```tcl
    foreach {Port Name} {inspect_core_clk InspectCoreClock core_csr_clk CoreCsrClock} {
        set Pin [get_ports -quiet $Port]
        if {[sizeof_collection $Pin]!=1} {error "Missing forwarded clock output $Port"}
        set Starts [lsort [get_object_name [all_fanin -flat -startpoints_only -to $Pin]]]
        if {$Starts ne "clk"} {error "Clock output $Port is not solely forwarded clk"}
        create_generated_clock -name $Name -source [get_ports clk] -divide_by 1 -combinational $Pin
        set_clock_uncertainty -setup 0.200 [get_clocks $Name]
        set_clock_uncertainty -hold 0.100 [get_clocks $Name]
        set_clock_transition 0.100 [get_clocks $Name]
    }
    if {[sizeof_collection [all_clocks]]!=3} {error "Expected root plus two forwarded output clocks"}
```

系统使用相同的compile_ultra映射选项，保存baseline后，对负hold裕量至多执行一次
hold-only增量修复并保存candidate。前后核对时序预算与冻结加速器清单，
输出系统SVF、名称映射、DDC、结构网表、SDC及原生面积/时序/设计检查报告。
完整代码见[系统Tcl快照](DCScripts_20261109/System/System.tcl)。

### 7.3 面积归属与结果含义

系统面积使用AreaBreakdown.tcl逐叶互斥分类，分别统计加速器逻辑/接口、私有宏、
CPU及内部ICB、共享ITCM宏、共享DTCM宏、共享TCM适配逻辑和其他逻辑。
加速器小计只包含前两项，已包含在系统总面积中，不能与系统总面积再相加。

系统映射和hold修复后，加速器小计仍为0.893356621584mm²，与独立加速器候选一致，

### 7.4 系统原生检查报告及解释边界

`check_timing.rpt`完成检查并返回1，但报告包含一项最大延迟未约束警告，

本轮clocks.rpt已核对：CoreCsrClock和InspectCoreClock均以clk为master source、CoreClock为master clock，

### 7.5 系统最差setup路径分析

本轮系统setup.rpt首条路径位于冻结加速器的矩阵结果转换逻辑，起终点均属于CoreClock时钟域：

- 起点：`u_e203_cpu/u_e203_nice_core/Tpu/Core/Matrix/ActiveShift_reg[3]`。
- 终点：`u_e203_cpu/u_e203_nice_core/Tpu/Core/Matrix/Result_reg[3][47]`。
- Path Group：`CoreClock`；Path Type：`max`；起终点均为上升沿触发寄存器。

本轮TpuMatmul.sv中，ActiveShift控制舍入结果的算术右移，并参与结果加偏置后的寄存。
相关RTL节选如下，Pipeline为生成循环中的结果通道索引：

```systemverilog
if (ResetN && RoundValid) begin
    Result[Pipeline] <= (64'(Rounded[Pipeline]) >>> ActiveShift)
                     + 64'(OutputBias);
    ConvertedAddress[Pipeline] <= RoundedAddress[Pipeline];
end
```

原生路径中可见缓冲、反相、组合选择逻辑，以及intadd_10和intadd_1下的连续进位单元，
反映了该结果生成逻辑的具体工艺映射。网表中的两段intadd层次不能直接解释为两条独立的RTL加法语句。

| 路径量                       | 原生报告数值（ns） |
| ---------------------------- | -----------------: |
| 发射时钟边沿 / 理想网络延迟  |              0 / 0 |
| 起点寄存器Q点增量延迟        |           0.625404 |
| Q点后至终点D的剩余路径延迟   |         约5.831651 |
| 数据到达时间                 |           6.457055 |
| 捕获时钟周期                 |           6.666667 |
| Setup uncertainty            |           0.200000 |
| 终点寄存器library setup time |           0.008672 |
| 数据要求时间                 |           6.457995 |
| Setup slack，MET             |          +0.000940 |

Q点后的剩余路径延迟由本条报告的累计时间相减得到，包含当前模型所计入的组合路径及负载/连线影响，
不是布局提取后的互连延迟。要求时间和裕量的关系为：

```text
required = 6.666667 - 0.200000 - 0.008672
         = 6.457995 ns
slack    = required - arrival
         = 6.457995 - 6.457055
         = +0.000940 ns
```

路径打印精度为6位小数；summary中以工具属性得到的WNS为+0.000940323ns，
两者在打印精度内一致。该路径满足当前布局前setup要求，但裕量仅约0.940ps。
它将当前系统最差建立时间路径定位到加速器矩阵结果转换的控制/组合逻辑；
后续物理实现仍需以实际时钟树、连线寄生与目标工艺角重新分析，不能由此保证布线后仍满足150MHz。
